# `agents/` Directory Layout Contract

> **Do not bypass this contract.** Every entry at the `agents/` root — file or
> directory — must appear in this table. Unknown entries are CI violations
> (`lint_agents_layout.ts` enforces this in source-repo mode, warns in consumer
> mode). Adding a new top-level entry requires a PR that also updates this table
> and the classification manifest (`src/config/agents-paths.yml`).

## Design invariants

1. **The `agents/` root stays flat-minimal.** Content lives in typed
   subdirectories. New flat files require a contract edit and explicit rationale
   (six whitelisted flat files exist; no new ones without a deliberate decision).
2. **`agents/tmp/` is the user's inbox; `agents/tmp.old/` is the processed
   archive.** The agent reads inbox files and moves them to `tmp.old/` after
   consumption. The agent's own scratch goes to `agents/runtime/tmp/` or the
   session scratchpad. See § User Inbox Workflow below.
3. **Both `tmp/` and `tmp.old/` are gitignored in every scope.** Consumer
   projects would commit their inbox without the managed block entry.

## User Inbox Workflow

```
agents/tmp/        ← USER drops notes, todos, draft ideas here
     ↓ agent reads + processes (roadmap create, memory promote, etc.)
agents/tmp.old/    ← AGENT moves the consumed file here, same reply
     ↓ janitor sweeps after 30 days
     (deleted)
```

**Rules:**

- `agents/tmp/` is the **user's space** — the agent only reads and moves from
  it; the agent never writes files into it.
- After consuming a file from `agents/tmp/` (as a command input), the agent
  moves it to `agents/tmp.old/<original-name>` in the **same reply** as the
  processing. No confirmation needed (gitignored, reversible, local-only).
- The agent's own scratch (intermediate calculations, session notes) goes to
  the **session scratchpad** or `agents/runtime/tmp/` — never into `agents/tmp/`.
- `agents/tmp/` is **never** auto-swept by the janitor — it belongs to the user.
  The janitor only touches `agents/tmp.old/` (TTL = 30 days).
- Both directories are gitignored in **package and consumer scope** (entry in
  `src/config/agents-paths.yml` with `scope: both`).

## Consumer-only scope (slim profile)

After `agent-config migrate`, a consumer project's `agents/` contains only:

| Entry | Rationale |
|---|---|
| `overrides/` | Per-project skill/rule customisation |
| `.event4u-bridge.yml` | ADR-020 bridge marker (global-only install) |
| `.gitkeep` | Keeps `agents/` in the tree |
| `knowledge/` | Optional: curated project-specific knowledge pages |
| `memory/` | Optional: promotion pipeline (intake gitignored, curated YAML committed) |
| `roadmaps/` | Optional: project-local roadmaps |
| `tmp/` | Optional: user inbox (gitignored) |
| `tmp.old/` | Optional: processed inbox archive (gitignored) |

Entries that are **not** expected in consumers (and that `agent-config doctor`
will warn about): `evidence/`, `decisions/`, `features/`, `reports/`,
`recruit-sessions/`, `settings/`, `roles/`, `reference/`, `roadmap-assets/`,
`notes/`, `tickets/`, `templates/`, `runtime/`, `state/`.

## Overlap decisions (2026-07-06)

| Pair | Decision |
|---|---|
| `evidence/` vs `reports/` vs `notes/` | **Keep `evidence/` as the umbrella.** `evidence/reports/` and `evidence/notes/` already exist as subdirs. New reports/notes land there. The top-level `reports/` and `notes/` are **legacy** — no new files; existing files can be migrated per future clean-up PR (non-blocking). |
| `memory/` vs `knowledge/` | **Keep both** with a crisp boundary: `knowledge/` = committed curated pages (human-reviewed); `memory/` = promotion pipeline (intake is gitignored JSONL; only curated YAML subsets get committed). |
| `templates/` vs `roadmap-assets/` | **Both empty/minimal — keep as reserved.** `templates/` = reusable agent-facing templates; `roadmap-assets/` = supplemental for specific roadmaps. New assets prefer `evidence/` sub-dirs unless they are true roadmap supplements. No migration needed today. |
| `recruit-sessions/`, `features/`, `tickets/` | **Keep all three** — distinct purposes, each has an active owner and lifecycle (recruit-sessions = user research; features = flag docs; tickets = bundle system). |

## What needs a contract edit

Any PR that:
- Adds a new top-level directory to `agents/`
- Adds a new whitelisted flat file to `agents/`
- Changes the git policy of an existing entry
- Changes the consumer-scope subset

...must update this table in the same commit, update `src/config/agents-paths.yml`,
and add the new entry to `ALLOWED_SOURCE_DIRS` (or `ALLOWED_FLAT_FILES`) in
`src/scripts/lint_agents_layout.ts`.
