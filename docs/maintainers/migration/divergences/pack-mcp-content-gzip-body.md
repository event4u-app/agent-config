# Divergence: `pack_mcp_content` gzip compressed-body bytes (zlib version)

## Script

- Python: `src/scripts/pack_mcp_content.py` (`gzip.GzipFile(..., compresslevel=9, mtime=0)`)
- TypeScript: `src/scripts/pack_mcp_content.ts` (`zlib.gzipSync` body + a rebuilt Python-shaped gzip header)

## Symptom

The gzip **header + FNAME field** (`content.json.gz` bytes `0 .. <NUL>`) are
byte-identical between the two runtimes — magic, CM, FLG, `MTIME=0`, `XFL=2`,
`OS=0xFF`, embedded `content.json\0` are all deterministic and rebuilt to
match. The **DEFLATE body** that follows is NOT byte-identical: on node 25 it
matched Python's zlib output, on node 22 (CI migration gate) the first/later
compressed bytes differ.

## Root cause

DEFLATE is not canonical — the exact compressed byte stream for a given input
depends on the zlib implementation and version (Python's bundled zlib vs
node's, and node 22's zlib vs node 25's). All variants are valid gzip and
decompress to the identical bytes; only the compressed encoding differs. The
gzip **metadata** (header + FNAME) is fully under our control and is byte-stable
(`mtime=0` removes the only timestamp); the **compressed body** is a zlib
implementation detail.

## Verdict

`formatting-only` — compressed-byte identity across two different zlib
implementations is not a reasonable parity target and carries no semantic or
consumer impact (the archival `.gz` is decompressed by its consumer; the bytes
within decompress identically). The real contract — identical **decompressed**
content — holds.

`content.json.gz` is a generated R2 archival artefact (denylist `skip_paths`),
regenerated by the deploy workflow; its consumer reads the decompressed
content, so a different-but-equivalent compressed encoding is immaterial.

## Evidence

`tests/scripts/pack_mcp_content.test.ts` → *"writes byte-identical content.json
/ content.json.gz / manifest.json"*:
- asserts the gzip header + NUL-terminated FNAME field byte-identical
  (`subarray(0, headerEnd)` where `headerEnd = indexOf(0x00, 10) + 1`),
  excluding the DEFLATE body;
- asserts the **decompressed** gz content byte-identical (modulo `built_at`),
  and that each runtime's `.gz` decompresses to its own on-disk `content.json`.
`content.json` and `manifest.json` themselves remain byte-identical (uncompressed).
