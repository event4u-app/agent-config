# ADR-295 — Removing a worktree on the proven set is housekeeping, armed by the user

## Status

Accepted 2026-10-21, on the owner's directive of the same day (filed verbatim
under `agents/evidence/owner-directives/`) and a council round of the same day,
2/2, which set the default and the hardening.

## Context

`worktree_cleanup_check` classed a squash-merged worktree as unmerged work
forever and removed nothing, so worktrees accumulated without bound — the owner
reported about 250 in one checkout, this checkout held 73. Its own header called
bulk removal a Hard-Floor action, although `non-destructive-by-default` never
names worktree removal. The owner asked for cleanup at the latest after the
merge, regularly, automatically where possible.

## Decision

1. **The proven set is housekeeping.** A worktree whose work is on the trunk —
   by the graph (`merged-ancestor`), by the forge (PR merged and the branch tip
   equals the PR head, `merged-pr`), or offline by tree equivalence
   (`merged-equivalent`) — that is clean, holds no ignored file outside the
   regenerable set, is not locked and has no live session, may be removed with
   `git worktree remove` without force. Every other removal stays a decision.
2. **It is an authority expansion, and declared as one.** Removing from a
   `session_start` path is acting, not observing (council 2026-10-21 Q1, both
   seats). The user-owned key `worktrees.cleanup` (class C, `consent`) arms it:
   `notify` (default — installation alone is not consent, Q2) reports and
   removes nothing; `auto` removes; `off` is silent.
3. **The hardening is part of the decision**, not an implementation detail:
   per-repository lock; every predicate re-checked immediately before each
   removal; subprocess deadlines for the three-second daily budget; a rotating
   start so no candidate starves; a journal line per candidate; a regenerable
   set limited to paths never hand-edited, the rest declared generated by the
   repository's own `.gitignore` comment.
4. **Branches are never deleted by this path.** `-d` and `-D` classify as the
   same operation, and the directive names worktrees.

## Consequences

- `/pr:merge` and the first session start of a day can remove worktrees when the
  user set `auto`. ADR-229's rule on **creation** is untouched.
- The daily pass makes one `gh pr list` call per repository per day, disclosed in
  the settings template.

## Alternatives

- **Detached removal process** — rejected 2/2: a process outliving the hook is
  harder to bound and to reason about than a synchronous budgeted pass.
- **`auto` by default for new installs** — rejected 2/2 (Q2).
- **A broad built-in regenerable list** (`dist/`, `vendor/`, `.venv/`) — rejected:
  each can hold a patched dependency or a kept artefact.
