## Phase 7: `/council debate` sub-command (multi-round rebuttals, progressive disclosure)

R4 Q2 verdict: debate mode lands as a **new sub-command**, not a flag on `/council default`. Rationale: debates change the orchestration shape (N members produce initial positions → each member rebuts the others → optional further rounds → final synthesis), which justifies a dedicated entry point with its own cost-disclosure UX. A flag would hide the cost multiplier behind an existing command. Cost stays predictable via **progressive disclosure**: after each round the orchestrator pauses, surfaces accumulated spend, and asks the user to continue. The user-facing pivot from a `/council default` run that wants to escalate is `/council debate --continue-as-debate <last-session-path>`, which seeds the debate's Round 1 with the existing responses instead of restarting.
