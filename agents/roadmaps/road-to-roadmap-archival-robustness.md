# Road to roadmap-archival robustness — completion archives without a PR

> Make "completed roadmap → archived" deterministic **independent of** the PR
> flow, git-tracked state, and vendored-script presence. A consumer working
> pre-first-commit, or closing a roadmap by direct edit, must never leave a
> 100%-done roadmap rotting in the active tree.

## Goal

Today archival has exactly two triggers and both can silently no-op:

1. **`/create-pr` § 1c** — runs `archive_completed_roadmaps.py`. Never fires if
   the project has no commit / no PR (work done directly on `main`).
2. **`/roadmap:process-*` § 6** — archives when `count_open == 0`, but delegates
   to a manual `git mv` (via `roadmap-management`) that **fails on untracked
   files**, and the regen/archive scripts may not even be vendored in the
   consumer.

The only backstop — `update_roadmap_progress.py --check` — is a CI gate, absent
in a fresh consumer. Result: completed roadmaps stay unarchived indefinitely,
and the agent-side inline-flip (Iron Law) is the sole guard, which is
model-discretion, not deterministic.

This roadmap closes the gap so completion → archival is robust across:
(a) no PR flow, (b) untracked / pre-first-commit repos, (c) script-less
consumers, with a non-CI backstop that makes "completed but unarchived" visible.

## Canonical repro (evidence basis)

Observed 2026-06-21 in the `capisco` consumer:

- `road-to-app-foundation.md` (`status: complete`, 19/19) and
  `road-to-design-primitives.md` (14/14) reached 100% via direct editing.
- Repo had **zero commits** (everything untracked), no `/create-pr` ever ran,
  and no `archive_completed_roadmaps.py` / `update_roadmap_progress.py` was
  vendored.
- Both roadmaps sat unarchived in `agents/roadmaps/`. The dashboard header even
  claimed `Auto-generated by .augment/scripts/update_roadmap_progress.py` — a
  path that did not exist in that project.
- Manual fix required: hand-create `archive/`, `mv` (not `git mv` — untracked),
  hand-recompute the dashboard.

Grounding in source (`src/agent-src/scripts/`):
- `archive_completed_roadmaps.py:89-93` — `git mv` only; `:123-124` prints
  `⚠️ git mv failed` and skips on failure.
- `--changed-only` default → `git log origin/main..HEAD`, empty without
  commits/remote.
- `update_roadmap_progress.py` — `--check` exit-1 backstop is CI-only.

## Phase 1 — Untracked-safe archival (gap A)

- [ ] `archive_completed_roadmaps.py`: detect when a target file is untracked
  (or the repo has no commits) and fall back from `git mv` to a plain
  `mv` + working-tree ref-rewrite, instead of printing `git mv failed` and
  skipping.
- [ ] Same fallback for the inbound-reference rewrite step — operate on the
  filesystem, not on the git index, when untracked.
- [ ] Unit test: untracked repo → roadmap archived, refs rewritten, dashboard
  regenerated, exit 0 (no `git mv failed` on stderr).

## Phase 2 — PR-decoupled trigger (gap B)

- [ ] Make `/roadmap:process-*` § 6 invoke `archive_completed_roadmaps.py --all`
  (script path) as the primary archival path, with the documented manual
  procedure as fallback only when the script is absent — not the other way
  round. Update `roadmap-process-loop.md` § 6 accordingly.
- [ ] When the archive/regen scripts are **not vendored** in the consumer,
  the loop must emit a clear one-line instruction (run `agents:init` / vendor
  the scripts) rather than silently delegating to a manual `git mv` that fails.
- [ ] Keep the `/create-pr` § 1c trigger as-is — this phase adds a second,
  PR-independent entry point; it does not remove the PR-gate.

## Phase 3 — Non-CI backstop + honest provenance (gap C)

- [ ] Dashboard regen surfaces a visible banner when `count_open == 0` roadmaps
  remain in the active tree (not yet archived) — so "completed but unarchived"
  is visible without CI.
- [ ] Fix the generated dashboard header: emit the **actual** regen path for the
  consumer (or a generic line), never a hardcoded `.augment/scripts/...` that may
  not exist in that project.
- [ ] Document the manual archival fallback (mkdir `archive/`, `mv`, ref-rewrite,
  regen) in `roadmap-management` so a script-less consumer has a correct path.

## Acceptance criteria

- An untracked, pre-first-commit consumer that closes a roadmap to 100% gets it
  archived (script run or loop § 6) with refs rewritten and dashboard regenerated
  — proven by a test, no `git mv failed` on stderr.
- A roadmap closed by direct edit (no `/create-pr`) is archived by the next
  `/roadmap:process-*` run, or flagged by the dashboard backstop banner.
- No generated dashboard claims a regen script path that does not exist in the
  consuming project.
- `/create-pr` § 1c behaviour is unchanged for tracked repos with a PR flow.
