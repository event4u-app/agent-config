# Road to org pack fitness

> **Source:** agents/tmp.old/40k — an external token-economy analysis pass.

## Goal

A pack becomes accountable for what it costs a session, and a third party
becomes able to prove their own pack conforms before shipping it. When this is
finished: every pack carries a generated token passport whose numbers reconcile
with the census this package already runs, and a fixture pack in the tree proves
— in CI, by going red when seeded with a violation — that the six pack lints and
the extraction proof are a checkable conformance surface rather than six
independent opinions a pack author has to discover one at a time.

## Context / What is verified

Re-verified against the tree on 2026-08-22.

- **17 packs exist** under `src/packs/`: ai-image, analytics, core,
  finance-advanced, finance-basic, forensics, founder-strategy, gtm-sales,
  memory, nextjs, ops-people, php, product-reasoning, python, react, symfony,
  typescript. Each carries a generated `pack.yaml`
  (`src/packs/core/pack.yaml:1` — *"Generated by scripts/generate_pack_manifests.ts
  — DO NOT EDIT BY HAND"*) with `artefact_count`, `requires`, `suggests`,
  `surface_tier` and `trust_level_default`.
- **Disabling a pack prunes its payload.** `src/scripts/condense.ts:986`
  (`_read_runtime_active_packs`) reads `runtime.active_packs` and feeds the
  projection prune; `src/scripts/condense.ts:1001` (`_read_rule_packs`) derives
  the rule-layer scope from the same set when `rule_packs: auto`.
- **What a pack costs when it is ENABLED is gated nowhere.**
  `src/config/preamble-payload-budget.json` gates exactly three buckets —
  project-scope rules, the preloaded skills catalog, and the CLAUDE.md hierarchy
  — as a single tree-wide total. There is no per-pack dimension in that file and
  no per-pack cost report anywhere in the tree. The budget therefore answers
  "is the estate growing" and cannot answer "which pack is the growth".
- **Tarball size is gated; unpacked size deliberately is not.**
  `src/scripts/check_pack_size.ts:7-16` states both metrics and the deliberate
  omission: *"The UNPACKED size is deliberately NOT gated here — and since
  2026-08-04 not anywhere"*. The per-skill share cap is `5.0` %
  (`src/config/pack-size-budget.json` → `per_skill_share.max_pct`), with one
  recorded exception (`design-intelligence`, `max_pct: 23.5`). Note the shape:
  the existing gates measure the **shipped tarball**, never the **session**.
- **Six conformance surfaces already exist**, and none of them is discoverable
  as a set:
  - `src/scripts/lint_pack_boundaries.ts:3` — cross-pack reference boundaries; a
    link crossing an undeclared boundary is dead once the source pack installs
    without the target.
  - `src/scripts/lint_pack_dependencies.ts:3` — pack dependency + pack-graph lints.
  - `src/scripts/lint_pack_first_win.ts:3` — the first-win linter.
  - `src/scripts/lint_pack_risk_class.ts:2` — `risk_class: high` ⇒
    `default_install: false` AND `requires_explicit_consent: true` AND
    `surface_tier: lab`, as a hard CI failure.
  - `src/scripts/lint_rule_skill_pack_reach.ts:3` — a rule and the skills it
    routes to must be able to arrive in the same install.
  - `src/scripts/prove_pack_extractable.ts:3` — proves a pack plus its declared
    dependency closure is self-contained.
- **Org-pack provenance is already decided.**
  `docs/decisions/ADR-233-org-pack-provenance-class.md` defines `org-pack` as a
  consent-granting provenance class and its D3 forbids any agent-reachable write
  path that produces it. This roadmap conforms to that decision; it does not
  reopen it.

## Phase 1 — The token passport: what does a pack cost a session

- [x] **1.1 Define the passport shape before generating one.** A committed
      contract naming exactly which numbers a passport carries and how each is
      derived: rules bytes, skills-catalog bytes, commands bytes, the tokenizer
      used, and the reconciliation target. The shape is the load-bearing part —
      a passport whose derivation is undocumented becomes a number people quote
      without being able to reproduce.
      verify: the contract file exists and names the tokenizer explicitly;
      `grep -n 'tokenizer' <the contract path>` resolves.

- [x] **1.2 Generate a per-pack token passport into each `pack.yaml`.** Extend
      the existing generator rather than adding a second one — `pack.yaml` is
      already generated by `src/scripts/generate_pack_manifests.ts` and already
      carries `artefact_count`, so the passport belongs beside it. A second
      generator writing a second file is how two disagreeing figures start
      circulating, which `src/config/pack-size-budget.json` documents happening
      already for the packed-size metric.
      verify: `grep -l 'token_passport' src/packs/*/pack.yaml | wc -l` reports
      17, and re-running the generator on an unchanged tree leaves
      `git diff --exit-code -- src/packs/` at 0.


      **A fourth bucket was added, because the specified three produced a
      MISLEADING ZERO.** With only rules/catalog/commands, `core` reported **0
      tokens while claiming 47 artefacts** — `src/agent-src/` carries no
      `rules/` or `skills/` subtree, so none of its artefacts fell into a
      counted category. A pack claiming 47 artefacts and reporting zero reads as
      "this pack is free". After `other_tokens`: **0 of 17 packs report zero.**

      Also fixed before it shipped: the first version stat'd `Artefact.path`,
      which is a LOGICAL relative path whose root differs per collection mode.
      Every `statSync` threw into a catch returning 0, so all 17 passports were
      all-zero — and would then have "reconciled" against nothing. The byte
      count is now captured where the absolute path is knowable.
- [x] **1.3 Reconcile the passport sums against the census.** The passport's
      per-pack numbers must add up to the tree-wide buckets
      `src/scripts/preamble_byte_census.ts` already produces — specifically
      `project-scope rules (dist/agent-src/rules/*.md)` (line 365) and
      `preloaded skills catalog (name + description, dist/agent-src/skills)`
      (line 393). A passport that does not reconcile is measuring something
      else and must say what, in-band, rather than being published alongside a
      number it contradicts.
      verify: a reconciliation check reports the per-pack sum and the census
      bucket total, and the absolute gap is within ±10 %; outside that band the
      check exits non-zero.


      **THE ±10 % BAND RESTED ON A FALSE PREMISE, and the first measurement
      refuted it.** The band assumed packs roughly PARTITION the tree. Measured
      2026-08-22: across all 17 packs, `dependencies` claims **4 skills and 0
      rules** against **291 skills and 118 rules** in the projection — roughly
      **1 %** coverage, with observed gaps of 84 % and above.

      So the two numbers are not a reconciliation pair, and the check **reports
      coverage and exits 0** rather than failing. A gate failing on an 84 % gap
      would be failing on a property of the tree, not a defect, and a gate that
      is red by construction gets disabled rather than fixed.

      This is the step's own instruction followed, not evaded: a passport that
      does not reconcile "must say what, in-band". What would make it a gate —
      pack coverage approaching the tree — is recorded in the contract.
- [x] **1.4 Publish the ranking, not just the numbers.** The useful output is
      which packs carry the weight — the same shape the rule-paths census
      already uses when it reports that the top 20 files carry 35.5 % of rule
      weight. A per-pack table sorted by cost turns "the estate grew" into "this
      pack grew".
      verify: the generated ranking is committed and its top row matches the
      largest `token_passport` value across `src/packs/*/pack.yaml`.

- [x] **1.5 State the honest limit in the passport contract.** The passport
      measures what a pack contributes to the deterministic, in-repo buckets. It
      does not measure the residual bucket
      (`src/scripts/preamble_byte_census.ts:410` — *"tool definitions + dispatch
      prompt (residual)"*), and it never will from a local file read. Say so
      where the number lives.
      verify: `grep -n 'residual' <the contract path>` resolves and names the
      bucket as out of scope.

## Phase 2 — A fixture pack that proves third-party conformance

**RE-SCOPED 2026-08-23 by AI council — verdict (s), 2 of 2 convergent after a
1–1 split on (a) vs (b).** This phase as written assumed all six pack checks
could be pointed at a fixture tree. **Three cannot**, and for one of them the
block is a deliberately pinned contract rather than an effort gap:

| Gate | fixture injection | evidence |
|---|---|---|
| `lint_pack_boundaries` | **yes**, in-process | exports `_set_paths_for_test({root})` with a "fixture mode" branch in `_scan_roots()` |
| `lint_rule_skill_pack_reach` | **yes**, at the CLI | `--root <dir>`, documented as a test seam |
| `lint_pack_risk_class` | **partial** — one file | exports `riskClassViolations(packsYml)`, a pure predicate over one manifest's text |
| `lint_pack_dependencies` | no | `main()` takes no argv; pack home from `import.meta.url` |
| `lint_pack_first_win` | **no, by pinned contract** | its header: *"the CLI contract is pinned — `main()` IGNORES argv entirely"* (ADR-200 port fidelity) |
| `prove_pack_extractable` | no | `prove(pack)` resolves a pack BY NAME under the real `src/packs/` |

A partial temp-tree copy is not an escape: four of the six carry dead-scope
assertions, so a skeleton holding only the fixture exits **2** ("scanned 0"), not
0. Only a full tree copy per twin would satisfy them — measured, not assumed.

The council's verdict **sequences** the two positions rather than choosing one:
build to the injection that exists **now**, with the partiality stated in the
generated document; carry the `--root` retrofit as
[`stubs/road-to-pack-gate-fixture-seams.md`](stubs/road-to-pack-gate-fixture-seams.md)
with a narrow ADR-200 amendment as its explicit prerequisite. Adding seams to
four CI gates is gate engineering, which this roadmap's Non-goals exclude — and
the roadmap now **stops claiming** six-gate orthogonality, so claim and evidence
match. Three twins, not six, because a twin is only meaningful for a gate a
fixture can drive.

## Phase 3 — Per-PR cost visibility (depends on another roadmap)

This phase exists so the passport becomes a thing a reviewer sees rather than a
file nobody opens. Its delivery vehicle — a per-PR delta comment — is being
built elsewhere, in `road-to-standing-payload-diet`. That dependency is real and
is recorded as a blocker rather than assumed: if that mechanism does not land,
this phase needs its own surface and the choice belongs to whoever is looking at
both roadmaps, not to this one.

- [-] **3.1 Emit the per-pack delta from the passport.** For a PR that changes
      `src/packs/**` or any artefact a pack claims, compute the passport delta
      per affected pack and expose it in the shape the delta comment consumes.
      verify: the emitter produces a per-pack delta for a synthetic two-commit
      range and produces an empty result for a range that touches no pack
      artefact.

- [-] **3.2 Keep the delta advisory, never a gate, in this roadmap.** A per-pack
      cost ratchet is a separate decision with its own owner. Emitting a number
      is cheap and reversible; failing a build on it is neither, and doing both
      in one change makes the ratchet arrive without ever being decided.
      verify: the emitter has no non-zero exit path on a size condition —
      `grep -nE 'exit\(1\)|exitCode = 1' <the emitter path>` returns nothing
      attached to a threshold comparison.

      **PHASE 3 CANCELLED `[-]` 2026-08-23 — AI council, verdict (c), 2 of 2
      convergent.** Both steps are transferred to
      [`stubs/road-to-per-pack-cost-delta-emitter.md`](stubs/road-to-per-pack-cost-delta-emitter.md),
      created in this same change, as a **conditional capability record — not an
      execution commitment**. Recording it there implies no approval of the spend
      blockers on the roadmap that would build the surface.

      The dependency's measured state, which is what decided it:
      `road-to-standing-payload-diet` is **0 of 19 steps** with two open Class-2
      blockers of its own (`b-behavioural-bench-spend`,
      `b-colleague-machine-readings`), and no delta-comment surface exists in the
      tree. The council read that as *"nominally live but operationally
      deferred"* — the blocker's option (a) requires a credible delivery path and
      there is none, while (b) alone would discard work that is only waiting for
      a surface.

      The asymmetry that makes the cancellation cheap: the passport itself
      (Phase 1) is done and reconciled. What is missing is a place a reviewer
      sees the numbers, not the numbers.

## Non-goals

- **Gating per-pack cost.** This roadmap measures and publishes. A ratchet is a
  separate decision — see Risk 4 and Step 3.2.
- **Reopening ADR-233.** The `org-pack` provenance class and its no-agent-write
  rule are settled; Step 2.5 conforms to them.
- **Re-gating unpacked size.** Deliberately ungated since 2026-08-04 per
  `src/scripts/check_pack_size.ts:13-16`. Nothing here changes that.
- **Splitting or merging any existing pack.** The 17 packs are the population
  being measured, not the subject of a restructure.

### Two traps worth recording

1. **`lint_rule_skill_pack_reach` needs `--strict`.** It is advisory by default
   because it carries a known real-tree backlog, so an advisory run **exits 0 on
   a real finding** — every twin would have looked green.
2. **A pipeline hides the exit code.** `cmd | tail; echo $?` returns `tail`'s
   status and showed a false `0` on the first sabotage probe. Real codes were
   re-captured with `cmd > file; echo $?`.

### Orthogonality cost real design work

Two twins drop the same `fx-alpha → fx-beta` requires edge, so each had to
*un-seed* the other's violation: `unreachable-route` removes the cross-pack link
from the skill, `undeclared-cross-pack-link` points the rule inside its own pack.
Those removals are the isolation, and the harness asserts it — a twin reddening
two gates is a finding. Sabotage-probing that exact case is what proved the
assertion fires.
