# Road to Self-Update + Global Hook Resolution

> Make `agent-config` a globally-resolvable binary, fix the Claude plugin hooks so they resolve it from PATH (passing `--project-dir`) instead of assuming a project-local wrapper, and give consumers two non-wizard refresh paths — so a global-only consumer repo's roadmap dashboard (and every other PostToolUse hook) actually fires.

## Goal

A consumer repo with no project-local install gets working hooks: the Claude plugin's PostToolUse command resolves `agent-config` from PATH, knows which project it fired in via `--project-dir`, and regenerates `agents/roadmaps-progress.md`. Ship the minimal dashboard fix first, then the `upgrade` / `refresh` command surface and the ADR-020 user-content-exception that legitimises a minimal `--project` surface.

- [x] Confirm the live failure on `agent-ide-plugin`: dashboard stale; no `agents/.event4u-bridge.yml`; no project-local `agent-config` wrapper; global `~/.claude/settings.json` has `hooks: {}`. (Verified during the diagnosis pass 2026-05-30.)
- [x] Confirm the Claude plugin hook command shape: `hooks/hooks.json` PostToolUse runs `"$CLAUDE_PROJECT_DIR"/agent-config dispatch:hook --platform claude --event post_tool_use --native-event PostToolUse`, generated by `condense.generate_plugin_hooks()` from `scripts/hook_manifest.yaml` (do not hand-edit `hooks/hooks.json`).
- [x] Confirm `roadmap_progress_hook.py._is_roadmap_touch` matches only relative paths (`startswith("agents/roadmaps/")`) and that Claude passes absolute `tool_input.file_path`.
- [x] Confirm `npm i -g @event4u/agent-config` already places `agent-config` on PATH (`bin` → `dist/cli/agent-config.js`).
- [x] Read ADR-020 (`docs/decisions/ADR-020-global-only-consumer-scope.md`) — consumer installs are global-only; only `agents/.event4u-bridge.yml` + `agents/overrides/` are project-local.

## Context

Why now:

- The roadmap-progress dashboard does not auto-update in the consumer repo `agent-ide-plugin`. Root cause is a chain, all verified in the 2026-05-30 diagnosis:
  1. The Claude plugin PostToolUse command calls `"$CLAUDE_PROJECT_DIR"/agent-config …`, assuming a **project-local wrapper**. Under ADR-020 global-only, the consumer repo has none → the command fails → no-op. This assumption itself contradicts global-only.
  2. The repo has no `agents/.event4u-bridge.yml` — it was never onboarded to the global-only model, so adapters cannot resolve the global root.
  3. Independently, `roadmap_progress_hook.py` matches only relative roadmap paths, but Claude passes absolute `file_path` → the matcher would miss even a correctly-wired hook.
- ADR-020 names **update lag** as a motivating problem: consumers should see new skills / rules / hooks "the moment they install or run [a global refresh] — no per-repo bump". A first-class self-update command operationalises that promise.
- `agent-config` is already an npm `bin`; making it reliably global-on-PATH is the missing link that lets the plugin hook resolve it without any project-local footprint.

Council convergence — AI council, members anthropic/claude-sonnet-4-5 + openai/gpt-4o, 2026-05-30 (two rounds):

- **Resolve `agent-config` from PATH** in the plugin hook, and **additionally pass `--project-dir "$CLAUDE_PROJECT_DIR"`** so the globally-resolved binary knows which project's `agents/roadmaps/` to scan. Without `--project-dir`, a PATH-resolved hook has no project context.
- **No `npx` fallback inside the hook.** PostToolUse fires per tool-call; an `npx` resolve/download per invocation adds a network round-trip and version drift. Fail loud instead, pointing at `agent-config doctor`; the installer verifies `which agent-config`.
- **ADR-020 needs a small "user-content exception" amendment** so a minimal `--project` surface (bridge marker + `agents/overrides/` + `.gitignore`) is explicitly legal. Forbidden remains: writing **distributed content** (skills / hooks / commands / `.augment/` / `.claude/`) into the repo.
- **Plugin-vs-binary update paradox:** the Claude plugin ships via marketplace on a cadence independent of npm. A newer plugin hook spec against an older global binary must be caught by a `--min-version` handshake in the dispatcher plus a `doctor` / installer PATH+version check.
- **Sequencing:** ship the minimal dashboard fix (Phase 1) independently of the command-surface redesign (Phases 2–3). Do not couple a critical bug fix to a large refactor.

Command surface (decided with the user 2026-05-30, council naming):

| Command | Scope | Behaviour |
|---|---|---|
| `agent-config upgrade` | global | Fetch + install the latest global binary + plugin. Non-interactive. The "update lag" fix. |
| `agent-config refresh --global` | global | Re-run the global install idempotently (same version). |
| `agent-config refresh --project` | project | Re-scaffold the minimal project surface — bridge marker, `agents/overrides/`, `.gitignore` entries. No wizard. Requires a bridge marker. |
| `agent-config init --project` | project | Wizard: create the bridge marker + overrides scaffold. |
| `agent-config doctor` | global | Verify `agent-config` on PATH, binary↔plugin version drift, bridge presence, plugin install health. |
| `agent-config` (bare, no subcommand/flag) | — | Error with guidance — never a silent global default. |

The existing `update` subcommand and `--global` flag are reconciled in Phase 3 (alias / deprecation, backward-compatible).

## Acceptance criteria

- A Claude PostToolUse roadmap edit in a global-only consumer repo regenerates `agents/roadmaps-progress.md` with no project-local `agent-config` wrapper and no `.augment/` / `.claude/` footprint.
- `agent-config` resolves from PATH; `upgrade` keeps the global binary + plugin current; `doctor` diagnoses PATH / version-drift / bridge state.
- `refresh --project` writes only the ADR-020-allowed project surface (bridge + overrides + gitignore); `refresh --global` is idempotent; bare invocation errors.
- ADR-020 explicitly exempts project-local user content; docs + `--help` describe the new surface.
- The original `agent-ide-plugin` failure is reproduced-then-fixed end-to-end (Phase 5).

## Open questions / risks

- **Marketplace plugin install path for consumers** — does the consumer onboard the Claude plugin via the marketplace, and does global-only onboarding wire plugin enablement? Resolve before Phase 5; may add a step to `init --project` / the wizard.
- **PATH on non-interactive shells** — Claude plugin hooks may run under a shell whose PATH lacks the npm global bin dir. `doctor` must detect this; the fail-loud diagnostic must name the fix. Validate during Phase 1/2.
- **Legacy `update` semantics in the wild** — any consumer scripts calling `agent-config update` must keep working through the Phase 3 alias.
