# Road to Lean Initial Context

> Cut the tokens loaded into an agent's context at session start, without weakening a single Iron Law. Measure first (the payoff ranges 15%–87% depending on one unverified fact), fix the live budget breaches, take the certain tool-agnostic wins, build the safety net, then make the per-tool projection genuinely thin.

## Goal

The always-on layer for every tool projection (`.claude/`, `.augment/`, `.cursor/`, `.clinerules/`, `.windsurfrules`) carries the kernel full-bodied and everything else as a thin trigger-pointer that the router resolves on demand — proven by a measured token baseline, guarded by a trigger-coverage suite so no needed rule silently fails to fire, with Iron-Law fences preserved byte-for-byte and a documented one-flip rollback to the current eager state.

Target architecture (batch-4 idea 24 — already where this roadmap points):

- **L1 always-on:** kernel rules + router + active persona/role only.
- **L2 discoverable:** artefact metadata, skill index, command index (name+description, budget-capped).
- **L3 lazy:** skill bodies, guidelines, contracts, examples, long docs.

The whole roadmap is the migration of artefacts down from "L1 by accident" (the eager-loading defect) to their correct level.

## Provenance

Built from a ChatGPT idea-dump (two batches, ideas A–N) adjudicated by an AI Council. Council (`anthropic/claude-sonnet-4-5` + `openai/gpt-4o`, 2 rounds with mutual critique, 2026-05-31) converged on:

1. **Instrument before optimizing.** The dominant uncertainty is whether any tool projection actually honors `dist/router.json` lazy-loading, or dumps all rule bodies eagerly. If eager, the ceiling is ~87% reduction; if already lazy, ~15%. A ~1-hour experiment decides which roadmap we are even running. This blocks everything.
2. **Fix the live budget breaches first** — you cannot trust measurements of an out-of-spec system.
3. **char ≠ token.** Every budget and savings claim in the suite is in characters; the goal is tokens. Measure tokens with real tokenizers.
4. **Frontmatter centralization** (idea E) is the one certain, tool-agnostic, low-risk win.
5. **Trigger-coverage tests are the #1 safety guardrail** before any kernel/lazy shrink — adversarial "task X must surface rule Y" cases.
6. **Idea H (dual machine-readable form) is an anti-pattern** unless re-scoped as a *generated* build artifact with a semantic-preservation proof.
7. **Idea I (rule-IDs / pointers) is partially shipped** (18 of 72 rules are already pointers) — audit the existing 18 for link-rot and discoverability before expanding the pattern.
8. **Idea K (task classifier)** is fail-unsafe as a blocking gate; acceptable only as a fast advisory hint with a latency budget + fail-open fallback. Defer.
9. Add a **rollback / kill-switch** and a **src→dist staleness guard**.

A second council round (`anthropic/claude-sonnet-4-5` + `openai/gpt-4o`, 2 rounds, 2026-05-31) adjudicated a discovery-surface idea batch and reframed the priority:

10. **The description catalog is the single biggest lever — bigger than the rules.** 129 skills + 141 commands at loose caps (skill 300 / command 500 / rule 500) ≈ 67–86k tokens loaded eagerly at start via progressive disclosure — ~1.85× the rules' ~36k. Tightening per-artefact description budgets is GENUINELY-ADDITIVE and **not** Phase-0-blocked (these descriptions are confirmed in initial context). #1 certain win.
11. **Extend cost-profiles to all artefact classes** (commands, skill-index, guidelines, personas, chat-history), gated on a cross-reference coherence audit (no `minimal`-profile artefact references a `full`-profile one).
12. **DROP two anti-patterns:** the two-stage/grouped skill index (breaks progressive disclosure — fix a big catalog with smaller entries, not by hiding them) and "never route guidelines" (guidelines are already second-hop trigger-loaded, never initial — removing routing is pure indirection for zero benefit).
13. **Everything else is hypothesis pending Phase-0 data:** `llms-minimal.txt` (only if `llms.txt` is actually loaded by ≥1 tool; must be *generated* from `llms.txt`, never hand-curated), command stub/body split (only if command *bodies* are loaded — else a 141→423-file refactor for ~0 gain), README separation, runtime-state summary.
14. **`tokens:audit` is not a new idea — it IS the Phase-0 instrumentation.** Folded into Phase 0, not listed as a separate lever.

Host caveat on idea 10 (description budgets): too-short descriptions cause skills to **under-trigger**; in this repo descriptions are deliberately pushy for trigger coverage (`description-assist` / `skill-quality`). So the budget cut is gated not only by a "can a human guess when to invoke?" read but by the Phase-2 trigger-coverage suite — a description that drops below the budget yet still fires every must-load case passes; one that stops a skill from surfacing fails.

A third feedback batch (ideas 11–24, technical depth) was adjudicated by the host agent's own adversarial pass — not councilled (the contentious architectural bets #13 and #21 are flagged below as optional council candidates). The load-bearing reframe: **most of batch-4 optimizes total/maintenance/on-demand cost, not INITIAL context** (this roadmap's sole goal). Verdicts:

15. **Usage-analysis → conservative archive (idea 23) — the strongest new lever.** It hits the #1 cost (the catalog) by removing never-loaded skills. Builds on the existing default-off telemetry. ADD to Phase 1, with conservative criteria (long window, human review — "never loaded yet" ≠ "useless").
16. **Persona-on-demand (idea 17) is already mostly true** — personas live under `personas/`, `role-mode-adherence` is `auto` (loads only when `active_role` is set), and no persona body appears in the eager context. Verify in 0B.5; otherwise no work.
17. **Already-aligned / fold, not new:** metadata-only discovery (12) = the existing progressive-disclosure + router; contracts-instead-of-rules (18) = the existing "body migrated to…" pointer + `contracts/`; progressive examples (20) = the lazy-ref work already in Phase 3; semantic compression (22) = the existing `triggers:` frontmatter.
18. **NOT initial-context levers (DRY/runtime, not start cost) — defer out of this roadmap's critical path:** delta-skills (15) and command-DSL (19) save ~0 initially because only one family member loads per request; router-caching (16) is a runtime reuse with staleness risk. Park as a separate "DRY + runtime" concern.
19. **DROP:** namespace-ID compression (11) — same class as the already-rejected rule-IDs; names stay human-readable, the cost is descriptions (~2KB of names is noise next to the catalog). Skill-families *as a way to hide the catalog behind summaries* (14) — same anti-pattern as the dropped two-stage index; families are fine purely as organization for delta-sharing.
20. **Council candidates (high-stakes, contentious):** embedding-router (13) conflicts with the Phase-2 determinism guarantee — fuzzy top-3 can't satisfy "task X MUST load rule Y"; rule-virtualization (21) can't compress an Iron Law into a boolean without losing the behavioral instruction (the kernel must stay prose; the settings/profile layer already is the safe slice of this idea). Both DEFER; council them before any build.

A third council round (`anthropic/claude-sonnet-4-5` + `openai/gpt-4o`, 2 rounds, 2026-05-31) adjudicated a structural idea batch (25–40) and corrected the savings expectation:

21. **The "60–90% without deleting content" claim is not credible.** These 16 ideas add ~20–30% *net-new* (one lens: 10–15%); the big numbers double-count Phase 1 (catalog) and Phase 3 (thin projection) already in this roadmap. Total reduction across ALL phases is the headline number — not the incremental contribution of these ideas.
22. **REJECT idea 32 (multi-level condensation full/compact/micro)** — "dual-representation cubed"; incoherent and conflicts with idea 33 (you cannot maintain three manual tiers AND auto-generate). Keep the existing single condensed level.
23. **REJECT idea 39 (anti-loading budget / hard per-session cap)** — fail-unsafe: a cap can silently starve a safety-critical rule mid-session, and is a denial-of-service vector (flood cheap questions early to exhaust the budget before safety checks fire). The hardest pushback in three rounds. Safe slice only: soft warnings + a `priority: critical` floor that always loads — which is what the kernel already is.
24. **Genuinely-new, worth adding (gated, late):** idea 31 skill-composition-graph (parent skill loads; sub-skills on demand) — needs a `requires:` frontmatter field + a dependency-chain test; idea 33 telemetry micro-summaries — **reference skills only, never behavioral rules**, with a kill-switch (revert if benchmark success-rate drops >3%); idea 35 semantic de-dupe — incremental tooling extending `audit_overlap.py`, feeds the catalog archive; idea 36 dist-time pruning — pre-compiled per-profile builds beyond the existing install-time packs.
25. **Close as already-shipped / duplicate-of-rejected / not-an-initial-lever:** 25 (=lifecycle 37), 26 (=task-classifier), 27 (=Phase-1 command catalog), 28 (=rule-IDs), 29 (contracts not initial), 30 (=rule-virtualization), 34 (interactive, not boot), 37 (shipped), 38 (=embedding-router), 40 (=packs already mutually exclusive).

## Context

Why now: ChatGPT's advice was ~70% already-shipped here (kernel, router schema, per-rule budgets, condensation, rule-authoring skills, audit command, progressive disclosure). The genuinely open levers are narrow and the package owner wants the initial-context cost down. The empirical trigger: in a live Claude Code session on 2026-05-31, all rule bodies — kernel *and* `auto`-tier (e.g. `domain-safety-*`, `persona-governance`) — were injected eagerly. If that is the real projection behavior, the router exists as data but is not applied, and making the projection thin is the single biggest lever in the suite.

Constraints that bind every phase:
- **Source of truth:** edit `.agent-src.uncondensed/` only, then `/condense`. Never hand-edit `.agent-src/`, `.augment/`, `.claude/`.
- **Iron-Law preservation:** `scripts/iron_law_sha.py --all-kernel` must stay green; fences byte-for-byte (per `preservation-guard`).
- **Kernel-rule edits** (`commit-policy`, `scope-control` in Phase 0A) get their own PR with the ≥24h soak per `scope-control § kernel-rule-edits`.
- **No version/date pins** in this file (per `scope-control`). Targets are stated as gates, not deadlines.

## Phase-exit benchmark gate (applies after EVERY phase)

Every token cut risks degrading *which* skill/rule the agent selects. The existing benchmark harness already measures exactly this, so it becomes the per-phase better/worse gate — no new harness needed:

- **Harness:** `scripts/bench_run.py` (selection-accuracy + token/cost + structural-quality per prompt, report under `internal/bench/reports/` per `docs/contracts/benchmark-report-schema.md`) and the A/B `task bench:ab` (`with` vs `without` arm, corpora under `internal/bench/corpora/`).
- **What it must show, after each meaningful phase:** (1) initial-token cost ≤ the frozen baseline (better or equal), AND (2) selection-accuracy — does the right skill/rule still get hit — not regressed beyond a locked threshold. A phase that lowers tokens but drops accuracy is a **failed** phase: revert or fix before the next phase.
- **Cost discipline:** the per-phase gate runs the **cheap** path (selection-accuracy + static token measurement, no live API). The **live** A/B (`task bench:ab:live`, real spend) runs only at major boundaries (after Phase 1, after Phase 3) and is surfaced for cost confirmation first.
- **Corpus coverage:** seed the bench corpus with the Phase-2 trigger-coverage cases plus the safety-critical rules, so "skills/rules still hit" is measured, not assumed. Extend the corpus when a phase touches a surface it does not yet cover (this is the "oder ein neuer" — grow the corpus, not a parallel harness).
- **Relationship to Phase 2:** trigger-coverage (Phase 2) is the deterministic *must-load* floor; the benchmark is the broader accuracy+cost regression signal. The floor blocks a known miss; the benchmark catches the unknown drift.
