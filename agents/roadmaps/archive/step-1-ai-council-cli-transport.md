# Roadmap: AI Council CLI Transport + Safety Net + Decision-Replay + Impact-Routed Lightweight QA

> Three coupled deliveries against the AI Council subsystem. **Part A — CLI Transport (Phases 0–5):** add a third transport mode `cli` alongside `api` and `manual`. When a council member is set to `mode: cli`, the orchestrator shells out to the provider's locally-installed CLI (`claude`, `codex`, `gemini`, optionally community `grok` / `perplexity`) instead of calling the SDK. CLI calls reuse the user's existing subscription auth (Claude Pro/Max, ChatGPT Plus/Pro, Google account, etc.) so spend is covered by the flat-rate subscription, never per-token billing. `billable=False` on the new client so the existing `cost_budget` gate skips it cleanly; a separate call-count guard keeps subscription quotas safe. **Part B — Safety Net + Decision-Replay (Phases 6–9):** stop the Council from firing when the request does not warrant it, stop using oversized models when a smaller one would suffice, make Debate-cost visible before tokens burn, and document why every consensus verdict happened. Addresses the GPT review of PR #148 ("council scope explosion / analysis theater / black-box token burn") without removing the feature — gates it behind classifier + cost-disclosure + user-override. **Part C — Impact-Routed Lightweight QA + Learning Corpus (Phases 10–12):** add a five-class impact classifier (`trivial` / `low_impact` / `medium_impact` / `high_impact` / `user_required`) that decides whether the agent resolves a pending question itself, routes it to a fast-path council, escalates to standard council, or asks the user. `high_impact` + `user_required` are structurally locked to the user — no override. `low_impact` routes to a strictly opt-in fast-path council member (1 round, ≤2 members, hard token + cost caps) with a transparency marker. A project-local `agents/low-impact-decisions.md` corpus collects examples behind a non-bypassable privacy-redaction Iron Law and a probation gate (3 confirmations within a rolling 30-day window before an entry moves from `## On Probation` to `## Validated`); only Validated entries feed the classifier and only Validated entries can be packaged by `/learn-low-impact` as a draft upstream PR to the agent-config package.

## Context

Today every billable council call costs real money per token. Most users running this repo already pay for Claude Pro / Max, ChatGPT Plus / Pro, or have a Google account that grants free-tier Gemini access — paying again per token through the API is wasteful when a local CLI already exists and is authenticated. The fix is a third transport on the existing `mode:` axis, not a new architecture: the `billable=True/False` flag already partitions cost-gated from free transports (Phase 2b of step-2), and `ManualClient` already lives at `billable=False`. The CLI clients slot in beside it.

CLI maturity as of 2026-05 (verified via vendor docs, not memory):

- **Anthropic Claude Code** — official, mature. `claude -p "<prompt>" --output-format json` returns `{result, cost_usd, session_id, is_error}`. Login via `claude login` (OAuth, persisted in `~/.claude/`). Canonical reference path for this work.
- **OpenAI Codex** — official, mature. `codex exec "<prompt>" --json` returns newline-delimited JSON events. Auth at `~/.codex/auth.json` after `codex login` (ChatGPT OAuth or device-code).
- **Google Gemini CLI** — official, mature. `gemini -p "<prompt>" --output-format json` returns structured output. OAuth via `gemini` interactive first-run.
- **xAI Grok** — **no official standalone CLI** as of 2026-05. xAI announced "Grok Build" in Jan 2026 but maturity is unverified. A community `grok` CLI exists (Superagent project) that wraps the API — uses an xAI API key, **does not** provide subscription auth. Phase 4 supports this opt-in as a thin wrapper but documents that it does NOT save money over `mode: api`.
- **Perplexity** — **no official CLI**. Community `@perplexity-cli/perplexity-cli` (npm) with `-p` flag exists; same caveat — wraps the API with an API key, no subscription auth. Phase 4 treats it identically to xAI.

Trade-offs locked into the design before any code:

- **Output-token tracking:** Claude's JSON wraps `cost_usd` and usage; Codex / Gemini JSON shapes differ. `session.md` records `usage.input_tokens` / `usage.output_tokens` for `api` calls — for `cli` calls those fields are `null` and `cost: subscription` replaces the USD line. Audit-trail discipline preserved; precision degrades intentionally.
- **Cost-gate bypass:** `billable=False` means `cost_budget.max_total_usd` does not apply. The subscription, however, has its own quotas (Claude Pro: usage limits per 5h window; ChatGPT Plus: message caps; Gemini free tier: per-day limits). Phase 1 adds a separate `cli_call_budget.max_calls_per_day` per-member counter, default unset, that the user opts into when a provider's quota matters.
- **Auth failure detection:** SDKs raise typed exceptions; CLIs print to stderr and exit non-zero. Each provider gets a stderr regex pattern set (`"please run `claude login`"`, `"AUTH_REQUIRED"`, `"OAuth token expired"`, etc.) so the CliClient returns a structured `error="auth_expired"` instead of opaque subprocess output.
- **Binary discovery:** `shutil.which(binary)` at client init; missing binary → `CliClientError("claude not on PATH; install Claude Code or set members.anthropic.binary: /full/path")`. No silent fallback to API — the user picked `mode: cli` deliberately.

This roadmap is **work-only** — no version pins, no tag plans, no release dates.

### Part B context — Safety Net + Decision-Replay

GPT's PR #148 review surfaced four risks once `cli` makes Council calls effectively free: **(a)** users will invoke `/council` on requests that do not warrant it ("analysis theater"); **(b)** every member runs the largest available model regardless of question complexity (overkill, slow); **(c)** `/council debate` token-burn is opaque before the user commits to it (black-box spend); **(d)** consensus verdicts ship without provenance — "why this decision, which dissent, which model influenced it" is unanswerable post-hoc. Part B answers each:

| Risk | Phase | Mechanism |
|---|---|---|
| (a) Unnecessary council | 6 | Necessity-classifier — skip silently for trivial requests; if user explicitly invoked, explain why it's unnecessary and ask once |
| (b) Model oversized | 7 | Size-classifier — suggest smaller model when request shape allows; toggle global + per-lens, default ON |
| (c) Debate cost opaque | 8 | Pre-flight cost estimate + mid-run progress; hard refusal above `debate.max_cost_usd` |
| (d) Verdict without provenance | 9 | `decision-replay.md` artefact per session: per-finding which models agreed, which dissented, evidence quality |

Part B is **out-of-scope** for memory-aware council (reading historical decisions from `agent-memory` to bias deliberation) — that requires a separate roadmap once `agent-memory` is wired into `scripts/ai_council/`.

- **Sibling roadmaps:** [`step-3-agent-user-persona.md`](step-3-agent-user-persona.md) · [`step-4-ghostwriter.md`](step-4-ghostwriter.md) · [`step-5-test-cleanup.md`](step-5-test-cleanup.md) · [`step-6-user-types-axis.md`](step-6-user-types-axis.md) — independent; can interleave with any. Part B Phases 6–9 may begin after Phase 0 (`cli` schema landed) — they don't require Phases 1–5 wired.

## Phase 1: CliClient skeleton + subprocess plumbing

One abstract `CliClient(ExternalAIClient)` base in `scripts/ai_council/clients.py` that all provider-specific CLI clients inherit from. `billable=False` (matches `ManualClient`). No provider wired yet — just the framework.

- [x] **Step 1 — `CliClient` abstract base:** New class with `binary: str`, `default_args: list[str]`, abstract `_parse_output(stdout: str, stderr: str, returncode: int) -> CouncilResponse`. Constructor takes `binary` (override) + `model` + `timeout_seconds` (default 120). `__init__` runs `shutil.which(binary)` and raises `CliClientError` on miss.
- [x] **Step 2 — `ask()` implementation:** Run `subprocess.run([self.binary, *self.default_args, user_prompt], input=system_prompt or None, capture_output=True, text=True, timeout=self.timeout_seconds)`. Catch `subprocess.TimeoutExpired` → `CouncilResponse(error="timeout")`. Catch `FileNotFoundError` → `error="binary_missing"` (binary disappeared between `which` and call). Pass `returncode` + `stdout` + `stderr` to `_parse_output`.
- [x] **Step 3 — Daily call counter:** Helper `_increment_cli_call_count(provider: str, limit: int | None)` reads `~/.event4u/agent-config/cli-calls.json`, resets entries older than the current UTC date, increments the per-provider counter, returns `CouncilResponse(error="cli_quota_exhausted")` when the per-day limit is breached. Wired into `ask()` BEFORE the subprocess fires.
- [x] **Step 4 — Generic auth-failure detection:** `_detect_auth_failure(stderr: str) -> bool` on the base class — provider-specific regex sets are injected via class attribute `_AUTH_FAILURE_PATTERNS: tuple[re.Pattern, ...]`. Hits return `error="auth_expired"` with `metadata={"hint": "<provider-specific re-auth command>"}`.
- [x] **Step 5 — Unit tests with subprocess mocking:** `tests/ai_council/test_cli_client.py` — mock `subprocess.run` to return controlled stdout/stderr/returncode; verify timeout / binary-missing / quota / auth-expired paths each produce the right `CouncilResponse.error`. No real binary required for the suite.

## Phase 6: Council-necessity classifier + skip / educate / force flow

GPT review of PR #148: "council scope explosion / analysis theater." The fix is a pre-flight classifier that decides whether the request actually warrants a council deliberation, with three exit paths driven by the user's intent signal.

- [x] **Step 1 — Necessity heuristic:** New module `scripts/ai_council/necessity.py` with `classify_necessity(prompt: str, lens: str, invocation: Literal["agent", "user_explicit"]) -> NecessityVerdict`. `NecessityVerdict = Literal["necessary", "borderline", "unnecessary"]`. Heuristic uses prompt-shape signals (architecture / multi-stakeholder trade-off / ambiguity markers / strategic-decision verbs → `necessary`; bugfix / syntax / single-file implementation / lookup → `unnecessary`; everything else → `borderline`). Document the exact trigger lists in [`docs/contracts/ai-council-config.md`](../../docs/contracts/ai-council-config.md).
- [x] **Step 2 — Three exit paths wired into the dispatcher:** `scripts/ai_council/council_cli.py` consults the verdict BEFORE any member runs. **(a)** Agent-initiated invocation + verdict `unnecessary` → skip silently, log `skipped_reason: necessity_unnecessary` in `session.md`, return to caller without firing members. **(b)** User-explicit invocation + verdict `unnecessary` → educate inline (one paragraph: "This request looks like <category>. Council typically adds value for <criteria>. Proceed anyway?") + ONE numbered-options prompt per [`user-interaction`](../../.augment/rules/user-interaction.md) (1=proceed / 2=skip). **(c)** Any verdict `necessary` or `borderline` → proceed normally; `borderline` adds a one-line note in `session.md` rationale.
- [x] **Step 3 — Toggle in `.ai-council.yml`:** New top-level block `necessity_classifier: { enabled: true, mode: "educate" }`. `mode` ∈ `{ "off", "educate", "block" }`. `off` = legacy behaviour (always run); `educate` = Step 2's three paths (default); `block` = skip silently even for user-explicit invocation when verdict is `unnecessary` (power-user opt-in). Per-lens override at `lenses.<name>.necessity_classifier.mode` (e.g. `lenses.analysis` keeps `educate`, `lenses.debate` might force `block` to prevent expensive debate-mode runs on trivial questions).
- [x] **Step 4 — Unit tests:** Parametrized over 20+ prompt fixtures spanning each verdict bucket; verify all three exit paths fire correctly per toggle setting; verify per-lens override beats global; verify the educate-prompt is suppressed when `invocation="agent"` (agent never asks the user mid-flow, only the user-explicit path triggers the question).
- [x] **Step 5 — Skill + contract update:** [`.agent-src.uncondensed/skills/ai-council/SKILL.md`](../../.agent-src.uncondensed/skills/ai-council/SKILL.md) gains a "When NOT to invoke" section that mirrors Step 1's `unnecessary` triggers, so the skill itself routes away before the classifier has to. ## Phase 8: Debate cost-visibility + hard refusal cap

GPT review of PR #148: `/council debate` is "latency explosion / token burn / analysis theater" without pre-flight cost transparency. Phase 8 adds a mandatory cost-disclosure before the first round and a hard refusal above the configured cap.

- [x] **Step 1 — Pre-flight estimate:** New helper `estimate_debate_cost(members, lens, rounds, prompt) -> CostEstimate`. Computes per-member `tokens_in_estimate` (prompt + system + per-round-overhead) × `rounds`, multiplied by each provider's published per-1k-token rate (seeded in `members.<provider>.pricing: { input_per_1k_usd, output_per_1k_usd }`). Returns `{ low_usd, expected_usd, high_usd, per_member: { … } }`. CLI-mode members return `cost: subscription` (not summed into USD totals but called out in the disclosure).
- [x] **Step 2 — Mandatory disclosure block:** Before the first round, `council debate` emits a structured block: "Debate estimated cost: $X.XX–$Y.YY across N members, M rounds. Members: [list with per-member cost or `subscription`]." The dispatcher then asks via ONE numbered-options prompt: "1=proceed · 2=reduce rounds · 3=remove paid members · 4=cancel." Skipped entirely when `disclosure.mode=off` (power-user opt-in).
- [x] **Step 3 — Hard refusal cap:** New `debate.max_cost_usd: <float>` (default `5.00`). When `high_usd > max_cost_usd`, the dispatcher refuses to start the debate — emits an error with the breakdown and instructs the user to lower `rounds`, drop members, or raise the cap. No prompt — refusal is unconditional. Progressive disclosure mid-run: after each round, log running cost and stop the debate cleanly if the actual spend exceeds `max_cost_usd` even when the estimate was under (real usage > estimate edge case).
- [x] **Step 4 — Disclosure toggle + tests:** New `debate.cost_disclosure: { mode: "always", show_per_member: true }`. `mode` ∈ `{ "always", "above_threshold", "off" }`. `above_threshold` triggers only when `expected_usd > threshold_usd`. Tests cover: estimate accuracy within ±20% of a recorded fixture run; the four numbered-options paths; the hard-refusal cap (over-budget); the mid-run shutoff; the subscription-member call-out.
- [x] **Step 5 — Cost-visibility for non-debate lenses:** Apply the same `estimate_*` helper to `/council analysis` and `/council default` as an opt-in `cost_disclosure.mode: "above_threshold"` (default off for these lenses — they're cheap enough that the prompt would be friction). Document the opt-in path in [`docs/contracts/ai-council-config.md`](../../docs/contracts/ai-council-config.md).

## Phase 9: Confidence explanation + decision-replay artefact

GPT review of PR #148: consensus scores ship as a single number without provenance. Phase 9 adds per-finding confidence rationale (`why 0.87, not 0.65`) and a session-level `decision-replay.md` that documents which models agreed, which dissented, and what evidence they cited.

## Phase 10: Decision-routing-by-impact classifier + schema

GPT + Claude review consensus: the current ask-the-user flow has no impact awareness — naming questions, idiom choices, and architecture decisions all land on the user with equal friction. Phase 10 adds a five-class impact classifier (`trivial` / `low_impact` / `medium_impact` / `high_impact` / `user_required`) and a routing table that decides where each class lands (agent, council fast-path, council standard, user). This is the framework Phases 11–12 build on. **Iron Law: `high_impact` and `user_required` ALWAYS go to the user — no toggle, no flag, no override.** Security, architecture, billing, tenant-boundary, schema-migration, and any production-destructive class is structurally `high_impact` regardless of how the question is phrased.

- [x] **Step 1 — `decision_resolution:` block in `agents/.ai-council.yml`:** Top-level optional block. Per-class `mode: agent | council | user` plus `council_mode: advisory_fast | standard` where applicable. Defaults: `trivial → agent` (no council call, agent picks with one-line rationale logged), `low_impact → council` (advisory_fast — guarded by Phase 11), `medium_impact → council` (standard — uses the existing default lens), `high_impact → user` (locked — schema validation rejects any other mode), `user_required → user` (locked — same). Include `confidence_threshold: 0.7` for `low_impact` — only routes to council when agent's self-rated confidence is BELOW the threshold (high confidence → agent resolves without spending council tokens).
- [x] **Step 2 — Impact-classifier implementation:** New `scripts/ai_council/impact_classifier.py`. Heuristic-based — keyword-token shape on the pending question, no LLM call. Keyword classes: `trivial` (naming · whitespace · comment-style · import-ordering · variable case), `low_impact` (Service-vs-Repository · idiom choice · DTO-vs-array · job-vs-sync at small scale · test extension), `medium_impact` (API-shape change · contract update · cross-module touch), `high_impact` (security · auth · tenant-boundary · migration · production · DB-schema · billing · secrets · destructive-bulk), `user_required` (anything explicitly fenced by user with "ask me", "review first", "plan only"). Output: `(class, confidence_0_to_1, rationale)`. Confidence scoring is rule-based, not learned — explainable.
- [x] **Step 3 — Wire classifier into ask-user path:** Single chokepoint where the agent is about to surface a numbered-options question. Run `classify_impact(question_text)` → look up routing in `decision_resolution.<class>.mode` → dispatch. `agent` mode resolves internally + writes a `Resolved internally: <class>` line into the active session artefact. `council` mode routes to Phase 11 (deferred until Phase 11 lands; until then `low_impact + council` falls back to user with a `Phase 11 not yet implemented` note in the log). `user` mode renders the question normally.
- [x] **Step 4 — Tests:** Parametrized over the five classes — at least three fixture questions per class covering hits, near-misses, and intentional mis-classifications. `high_impact` and `user_required` MUST land on user even when `mode:` is set otherwise (validation rejects the override). Confidence-threshold edge cases: `low_impact` at confidence `0.9` skips council; at `0.5` triggers council; the `confidence_threshold` field is per-class settable.
- [x] **Step 5 — Contract + rule update:** [`docs/contracts/ai-council-config.md`](../../docs/contracts/ai-council-config.md) gains a "Decision routing by impact" section with the five-class table + the locked-class invariant. Update [`.augment/rules/ask-when-uncertain.md`](../../.augment/rules/ask-when-uncertain.md) (or add a delegate rule in `.agent-src.uncondensed/`) noting that questions classified as `low_impact` may route to council when Phase 11 is live — `high_impact` always asks the user. The Iron Law clause is new wording, not a softening of the existing rule.

## Phase 11: Lightweight-QA fast-path — per-member opt-in + hard caps

The actual feature — when a question classifies as `low_impact` and council is enabled, route to a designated fast-responder council member instead of the user. Strictly opt-in per-member (default OFF) so subscription quota / token spend can't surprise. Fast-path: 1 round, 1–2 members max, hard token cap. Output carries a visible transparency marker so the user always sees that a question was council-answered, not agent-answered or user-answered.

- [x] **Step 1 — `participate_low_impact:` per-member field:** Add the field to each member block in `agents/.ai-council.yml` schema, default `false` — explicit opt-in. Schema validation: meaningful only when the member's `enabled: true` AND global `decision_resolution.low_impact.mode: council` AND global `ai_council.enabled: true`. Any other state → field is parsed but treated as `false` with a one-line config-loader warning ("`participate_low_impact: true` ignored — member/council disabled"). Naming follows GPT-feedback consensus — verbose-but-clear over `cheap_questions` / `easy_qa`.
- [x] **Step 2 — `_resolve_low_impact()` orchestrator:** New function in `scripts/ai_council/` that (a) collects all enabled members with `participate_low_impact: true`, (b) sorts by speed-cost rank (cheapest provider first; within provider, smallest model first), (c) takes the top `decision_resolution.low_impact.max_members` (default `2`), (d) issues a single 1-round prompt asking for a short answer + one-sentence rationale, (e) returns the first responder's answer when `max_members: 1`, or a quick consensus (agreement → answer; disagreement → escalate to user with both opinions surfaced) when `max_members: 2`. Hard caps: `max_rounds: 1` (locked), `max_tokens: 2500` (configurable), `max_cost_usd: 0.05` per resolution (configurable). No advisor personas, no external-method peer-review, no consensus scoring — fast path strips all of step-2's debate machinery.
- [x] **Step 3 — Output format + transparency marker:** Agent's response prefixes the resolved answer with `> Resolved via low-impact council (<member-name>):` (markdown blockquote, one line). Below the marker, the answer + the one-sentence rationale. The active session artefact gets a one-line entry under `agents/council-sessions/<date>-<slug>/low-impact-resolutions.md` (one file per session, append-only): `<timestamp> · <question-class> · <member> · <answer-summary>`. When `max_members: 2` and members disagreed, the marker reads `> Low-impact council split — escalating to user (Claude: X / Codex: Y):` and the normal user-question flow continues.
- [x] **Step 4 — Negative + boundary tests:** `ai_council.enabled: false` → feature unavailable, classifier still runs but `low_impact` falls to user. All enabled members have `participate_low_impact: false` → falls to user. Classifier returns `high_impact` with confidence `0.4` → still goes to user (locked-class invariant from Phase 10). Hard-cap hit (token budget exceeded mid-call) → response truncated, marker reads `> Low-impact council aborted (token cap) — escalating to user:`. Provider rate-limit / auth failure → silent fallback to user with one-line log entry; never blocks the agent.
- [x] **Step 5 — Skill + observability:** Update [`.agent-src.uncondensed/skills/ai-council/SKILL.md`](../../.agent-src.uncondensed/skills/ai-council/SKILL.md) with the fast-path semantics + the transparency marker as a worked example. Add `--low-impact-stats` flag to `/council replay` (Phase 9) that summarises the session's low-impact resolutions: count, classes touched, members used, total cost. Cross-reference Phase 10's Iron Law in the SKILL so future agents reading it know `high_impact` is structurally locked.

## Phase 12: Low-impact-decisions learning corpus + probation gate + `/learn-low-impact` upstream PR command

Counter-validated learning loop with an explicit probation period. When the user signals "leichte Frage" / "low-impact question" the agent records the redacted, English-translated question into `agents/low-impact-decisions.md` under `## On Probation` with a timestamp. The same question signalled three times within a rolling 30-day window gets promoted to `## Validated` and from that turn forward the Phase 10 classifier routes similar questions as `low_impact`. Individual timestamps older than 30 days are pruned; an entry whose timestamps all expire silently drops out of probation. Promotion is one-way — a Validated entry never falls back. **Naming:** GPT review of PR #148 flagged "cheap" as wertend + product-grade-poor — the file is `low-impact-decisions.md`, matching the `low_impact_resolution` schema from Phase 10. **Iron Law:** nothing leaves the project repo until the privacy-redaction pass clears it. No secrets, no PII, no customer names, no internal URLs, no project-rooted paths.

- [x] **Step 1 — `agents/low-impact-decisions.md` template + four sections:** Create the file with: `## On Probation` (entries with ≥1 timestamp, awaiting threshold — entry format `- "<English question>" — first-seen <YYYY-MM-DD> · seen [<YYYY-MM-DD>, <YYYY-MM-DD>, …]`), `## Validated` (entries with ≥3 in-window confirmations, timestamps stripped — entry format `- "<English question>" — domain: <naming|style|structure|test-coverage|minor-refactor> · validated <YYYY-MM-DD>`), `## Anti-Examples (Always Ask User)` (questions that LOOK low-impact but aren't — security / architecture / migration / billing traps; captures Matze's "soll ich es in den Controller schreiben"-style trap), `## Security & Privacy Floor` (Iron-Law clause + forbidden-content checklist). Footer: `## Provenance` + `last-upstreamed: <git-sha>` line. File is git-tracked.
- [x] **Step 2 — Intake trigger + dedup + redaction:** Recognise user trigger phrases — German "das ist eine leichte Frage" / "mach das selber" / "löse das im council" / English "low-impact question" / "council should answer this" / "you should know this yourself" / equivalents. On match, agent (a) translates the most-recently-asked question to English, (b) runs the redaction pass (Step 4), (c) shows the redacted version with a confirmation prompt ("Add this as a low-impact decision example? Y/n"), (d) on confirm runs a semantic-match check against existing `## On Probation` and `## Validated` entries — match heuristic is exact-after-normalisation (lowercase, strip punctuation, collapse whitespace; no fuzzy/embedding match in v1, keeps it auditable). Match in Probation → append today's date to that entry's `seen` array. Match in Validated → no-op (already learned), log "duplicate of validated entry" to the session artefact. No match → new entry under `## On Probation` with today's `first-seen` + `seen [<today>]`.
- [x] **Step 3 — Probation gate (promote + prune):** New `scripts/ai_council/probation_gate.py` runs at council-startup AND after every intake append. **Prune:** for each `## On Probation` entry, drop any timestamp older than 30 days from `today` (UTC); other timestamps stay. If the `seen` array empties, drop the entire entry (the question never accumulated enough signal). **Promote:** count timestamps within the trailing 30-day window; if `count >= 3`, move the entry to `## Validated` (drop the `seen` array, add `validated <today>`). Promotion is one-way. Log a one-line summary per run ("pruned N stale timestamps; promoted M entries; dropped K expired entries") to the active session artefact. Idempotent — running the script twice in a row is a no-op on the second invocation.
- [x] **Step 4 — Hard privacy floor + redaction script:** Non-bypassable. New `scripts/ai_council/redact_low_impact_entry.py` with forbidden-content list — secrets (key prefixes per `scripts/check_no_secrets.py`), emails, project-rooted paths (any path starting `/Users/` / `/home/` / `/opt/` / drive letters / the configured repo root from `.agent-settings.yml`), customer / tenant names (generic terms `<customer>` / `<tenant>` / `<account>` survive; specific names don't), internal hostnames (`*.internal` / `*.local` / project-private domains from `.agent-settings.yml`), monetary amounts, SQL table/column names that carry business context, inline code excerpts longer than 40 characters. Redaction failure → refuse to save, surface the offending pattern to the user, instruct rephrase or skip. New rule `.augment/rules/low-impact-corpus-privacy-floor.md` carries the Iron-Law clause; the intake confirmation prompt cites it so the user sees the gate is real.
- [x] **Step 5 — `/learn-low-impact` upstream PR command + classifier feedback loop + tests:** New slash command at `.agent-src.uncondensed/commands/learn-low-impact.md`. Steps: (a) diff `agents/low-impact-decisions.md` against the `last-upstreamed: <git-sha>` baseline, (b) collect new `## Validated` entries ONLY (probation entries never upstream — they're unconfirmed), (c) re-run the redaction pass on each (defence in depth, second gate before leaving the repo), (d) reuse the `upstream-contribute` skill to open a DRAFT PR adding entries to `.agent-src.uncondensed/data/low-impact-decisions-seed.md` in the agent-config package, (e) advance `last-upstreamed: <new-sha>`. The command runs only when the user invokes it — no automatic upstreaming. Phase 10's classifier reads BOTH `## Validated` (project-local) AND the upstream seed at startup; `## On Probation` entries do NOT influence routing. **Tests:** each redaction pattern class fires correctly; intake appends timestamps correctly; dedup hits exact-after-normalisation; prune drops stale timestamps but keeps fresh ones; 3-in-30-days promotes; 2-in-30-days does not; promoted entry influences classifier on next run; probation entry does not influence classifier; upstream PR includes only Validated entries; PR is `draft`, never auto-merged.
