# Road to a failed command the recorder sees

> **Source:** `agents/tmp.old/inbox-2026-10-a/` — a round of sixteen external
> reviews of the 16.2.0 release plus a supplied scorecard rescore whose sixth
> fold names the exit-code record on claude as the stop lane's next blocker.
> Verified against `main` at `9bc8cd4f2` on 2026-10-01; disposition at
> `agents/evidence/analysis/inbox-2026-10-a-disposition.md`.

## Goal

A verification command that fails on claude leaves a run record with its
non-zero exit code, so detector C can refuse on a real failure instead of only
ever seeing passes. Done means: the native event a failed Bash call arrives on is
established by an observed session rather than inferred, the recorder is bound
to it, a fixture envelope for a failing `tsc` produces `FAIL_EVIDENCE`, and a
per-host reading states how often a verification candidate leaves no usable
record at all.

## Context

- `agents/evidence/analysis/verification-classifier-before-after-2026-09-30.md:73-85`
  records 24 run records on claude, zero with a non-zero `exit_code`, and a
  failing `npx tsc --noEmit <missing file>` (exit 2) absent from
  `verification_runs` — filed with an undetermined cause.
- `docs/contracts/hook-architecture-v1.md:796` quotes the host's tool events as
  `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest` and
  `PermissionDenied`.
- `PostToolUseFailure` occurs **0** times in `hooks/hooks.json`,
  `src/scripts/hook_manifest.yaml` and `src/scripts/hooks/host_lowering.yaml`;
  `hooks/hooks.json:53-60` binds the recorder's `post_tool_use` list to
  `PostToolUse` only.
- Working hypothesis, `corrected-from-reproduction`: the source's fold says "the
  exit code does not arrive on claude"; the tree says a failed call may arrive
  on an event nothing listens to. That is a hypothesis until Phase 1 observes it.

## Phase 1 — Observe which event a failed call fires

- [ ] **1.1 Capture the raw envelope of a failing Bash call.** In a scratch
      project outside this repository, register a one-line hook on both
      `PostToolUse` and `PostToolUseFailure` that appends the event name and the
      envelope's keys to a file under `agents/runtime/tmp/`, run one session that
      executes `false` and one that executes `true`, and record host, host
      version (`claude --version`), date and both envelopes in
      `agents/evidence/analysis/failed-tool-call-event-<date>.md`.
      verify: `grep -c 'PostToolUse' agents/evidence/analysis/failed-tool-call-event-*.md` -> /^[1-9]/
- [ ] **1.2 Pin the observed shape as a fixture.** Add the captured failing
      envelope, keys only and secrets-free, under
      `tests/fixtures/hook-envelopes/claude-bash-failure.json`, and a test that
      feeds it to `before_complete_hook.ts` and asserts the record it writes. The
      test is written to fail on the current binding.
      verify: `npx vitest run tests/hooks/before_complete_failure_envelope.test.ts` -> 1

## Phase 2 — Bind the recorder where the failure arrives

- [ ] **2.1 Route the failure event to the existing concern list.** If 1.1

## What this roadmap deliberately does not do

- It does not make detector C stricter. A high instrument-gap rate is answered
  by fixing the carrier, never by refusing on a gap — the source says so in as
  many words, and `INSTRUMENT_GAP_REASONS` already encodes it.
- It adds no new canonical hook event and no new detector.
