# Road to a thinned layer measured in one unit

> **Source:** an external comparison round against two harness trees (opaque
> ids S1, S2). The second keeps its instruction weight under test with three
> habits this file borrows as questions, not as code: measure the unit that is
> loaded, state each contract once, and sort every cut by how often it is paid.
> Every anchor re-read and every number re-measured at `main` @ `df377ca64` on
> 2026-10-05, then re-run by an independent pass. Phase 4 was added in a
> second round the same day, after an owner directive that a change the
> package makes to its own rules should be confirmed by a council at the
> least. Class: external comparison corpus.
>
> Round `agents/tmp.old/inbox-2026-10-d/`. Re-verified anchor by anchor at
> `main` @ `975d03d01` on 2026-10-05 by five independent read-only passes;
> the one commit since the pin moved no anchor, and their corrections are in.

## Goal

The thinned layer's standing weight is one number in one unit, read off a real
install. The stub form stops paying for its own description 89 times. And the
distance that then remains to the recorded ceiling sits on one page with a price
on each move that could close it. The moves that change what a rule obligates
are then put to a council, one question each, and taken where it permits them.

## Context

Reproduced on 2026-10-05 at `df377ca64`: installer bundle built from that tree,
global Claude install into an empty `HOME` with `lean_projection.mode: delivery`
on the user-global layer.

## Phase 4 — The moves a council may permit

Four of the five `no_stub` members project full-bodied because their law
stands in a fence or a list under no law heading; the fifth,
`legal-safety-floor`, is 23 characters over the law ceiling. Each row gives
its reason. One says it outright: promoting a block to a law heading "is
authoring a law, which is a change to what the rule obligates", and the rule
stays full-bodied "until a law section is written deliberately"; another
calls the heading "a rule edit rather than a projection one"
(`src/config/rule-consequence-class.json:118-140`). The archived decision put
that authoring under `artifact-drafting-protocol`
(`agents/roadmaps/archive/road-to-rule-laws-that-can-stand.md:114`), whose
batch clause reads: "In roadmap-run batch mode the human decision is the
contract acceptance" (`src/rules/artifact-drafting-protocol.md:52-54`). The
contract meant there is the execution contract a run derives and the user
confirms when it starts — a roadmap's own frontmatter "grants nothing"
(`src/agent-src/contexts/execution/roadmap-execution-contract.md:15-24`). So
the owner's decision for these four changes is the confirmation of the run
that takes this phase, with the four rule files named in it; a run without
that confirmation drafts them interactively, one prompt each. None of the
five is a kernel rule, and no hook or gate at the pin stops the edit.

## What this roadmap deliberately does not do

- No class member moved and no rule shortened beyond its law heading. No law
  heading lands without a council's verdict about it.
- `legal-safety-floor` is priced and not touched. Moving text out of its
  standing law lowers what stands, and a recorded safety floor is the owner's.
- No rule bodies copied anywhere and no change to what an install deploys; the
  install layout is frozen and its blocker is open.
- No edit to a kernel rule, no index file in place of stubs, no second ceiling
  gate, no default flip.
- No byte ratchet on skill bodies as a payload measure: they are not standing
  text, and the shared-phrase scan found nothing to remove.
