# Road to stop hooks that count own edits

> **Source:** the owner's session retrospective of 2026-11-21 (~380 Claude Code
> sessions across seven repositories), P0 measure 6 plus the hook false
> positives of its friction section: the stop hook asked for a review of 703,
> 951 and 9958 lines a read-only session never wrote; `docker exec … pest`,
> `tools/test` and Python checkers were not seen as verification, costing an
> extra run or note in almost every turn in five consumer repositories; the
> credential guard fired on the string `.env`; a `git fetch` was read as a push;
> the legal work-product line appeared 18 times in one session, mostly on
> conversational replies. AI council round of the same day (members anthropic
> and openai): openai required that a foreign-diff false alarm be reproduced and
> the attribution of edits to sessions be settled **before** hooks are limited
> to own edits — Phase 1 and step 2.1 exist for that. Owner constraint of the
> same day: no hand-maintained or owner-written context file; every project
> fact used here is read from the repository by a command.

## Goal

A session that wrote nothing is never told to review lines; a session that
wrote N lines is charged N, not N plus a parallel session's work. A project's
own test entry points — run through a container, a `tools/` script, a Python
checker or a Taskfile task — clear the turn-end verification detector. A
`git fetch` never triggers the push-settle reminder, and a `.env` token that
names no file to read is not refused. Each of these is pinned by a test that
was red before its fix.
