# Roadmap: Employee Product + External Proof — close the two adoption gaps

> Synthesis of two post-3.1.1 feedback rounds. Feedback A (Internal AI OS lens, 8.9/10) names the **product gap** — architecture is A+, but the surface is still "engineers built an AI platform", not "employees use an AI product". Feedback B (Adoption lens, A 116/120) names the **proof gap** — 4839 tests, 0 confirmed external users; the remaining four points do not live in the code (DE: *die letzten 4 Punkte liegen nicht im Code* · EN: the last 4 points are not in the code). Both gaps share a single shape: we have stopped being blocked by what's missing inside the package, and we are now blocked by what's missing outside it. This roadmap closes both — fast wins first (MCP listing in 30 min, content-creator path in 1 h, CI hardening in 1 day), then external proof (recruit sessions), then the structural employee-product surface (daily workspace, role UX, non-technical explain, single-user knowledge, document workflows, quick-actions launcher), with explicit Hard-Floor honesty for the team-deployment pieces that legitimately stay cancelled in the prior archived roadmaps.

## Context

The package's last 8 review sessions all converged on the same diagnosis: technical excellence has been re-validated, but the gap between "demo for a developer" and "tool a non-technical employee uses daily" is widening, not closing, because each release adds capability (video pipeline, multi-pack, GUI, MCP, council, explain, FIRST_WIN) without consolidating the **surface** those capabilities are reached through. A galabau owner / content creator / consultant / sales rep doesn't think in packs / trust levels / council / manifests; they think in plain task names (DE: *Angebot schreiben · Mail beantworten · Kunden vorbereiten · Video erstellen* · EN: write an offer · reply to mail · prepare for a customer · produce a video). Today every one of those tasks is reachable from the package, but only via the developer mental model.

This roadmap separates **what is cheap and high-leverage** (Phases 0–3 — adoption proof, fast wins, single-user knowledge) from **what is structural and council-gated** (Phases 4–9 — daily workspace UI, role experiences, document workflows, deployment hardening). Phases 0–3 ship in weeks. Phase 4 is the first multi-month structural commit and gates everything after it.

- **Strategic frame:** every phase ships an artefact a non-maintainer can show another non-maintainer, OR removes a friction point that blocks the next non-maintainer.
- **Sources:** Feedback A + Feedback B as delivered in chat 2026-05-24; archived `road-to-internal-ai-os-deployment.md` for Hard-Floor boundaries; archived `road-to-product-adoption.md` for the deferred-human-owner items it inherits.

## Phase 7: Analytics surface — turn the inert telemetry into a question

3.1.0 landed the telemetry SDK + Worker source-only; the Worker is not deployed and the kill-switch defaults off.
