| 1 | high | src/scripts/_lib/git_convention_carrier.ts:134 | `remoteSha` runs `git ls-remote --heads origin <bare>` and takes the SHA of the first output line. ls-remote patterns match any ref whose tail is `<bare>`, and output is sorted by refname, so with a branch `backport/main` (or `fix/main`, `release/x/main`) on the remote the first line is that branch, not `refs/heads/main` (reproduced in a scratch repo: `backport/main` listed first with a different SHA). `update_strategy` is then read from `.git-convention.yml` at the wrong commit, and `sync_pr_branch`'s target identity uses the same wrong SHA. The helper was moved from `sync_pr_branch.ts`, but this branch makes it the load-bearing source of the authority commit. Query the exact ref `refs/heads/<bare>` and match the refname column. | open | |
| 2 | high | src/skills/git-workflow/references/branch-update.md:96 | The rebase sequence takes the publish target from `@{push}`, which equals `@{u}` under `push.default=upstream`/`tracking`. A branch cut with `--track origin/main` therefore resolves `RB=main` (verified: `@{push}` → `refs/remotes/origin/main`). With no PR there is no cross-check, step 2's stop passes because `origin/main` is an ancestor of HEAD, and step 4 runs `git push --force-with-lease=refs/heads/main:<sha> origin HEAD:refs/heads/main`, publishing the feature branch onto the base. The page says "never against the base branch itself" and the opposite of using `@{u}`, but no step enforces `RB != BASE`, or any guard against a protected/default branch. | open | |
