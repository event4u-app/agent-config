## Goal

The single path behind the largest share of this repository's merge conflicts —
`agents/roadmaps-progress.md` — is no longer tracked, and its freshness gate
tells tracked and untracked apart **explicitly** rather than by inferring intent
from a missing file. The second-largest **authored** conflict surface, the
appending stubs index, stops appending. Two further generated paths the conflict
tool still routes to a human decision are classified. Everything the council
refused to greenlight — the consumer rollout, the estate-budget history split,
the gate-baseline split — is carried with its named blocker rather than shipped
half-analysed.

**F3 — the repo-side blocker is one comparison, and it reproduces.**
`update_roadmap_progress.ts:1337` sets `current = fs.existsSync(target) ? read : ''`
and `:1360` sets `stale = current !== new_text`, so an absent file is
indistinguishable from a stale one. Probed in a scratch worktree on `c00df51c6`,
failing direction first: with the file present `--check` exits **0**
(`✅ … is up to date`); with the file deleted it exits **1**
(`❌ agents/roadmaps-progress.md is stale`). The tree was restored from a `cp`
backup and verified clean (`git status --porcelain` empty, 312 lines back).

**F4 — the generator's self-header makes a claim untracking falsifies.**
`:1002` writes *"(timestamp lives in git history)"*. Once the file is untracked
there is no git history for it, so the header would assert something false about
its own provenance.

**F5 — the stubs index has no generator.** 133 lines of hand-written prose,
**zero** `- [` list items; every roadmap-transfer session appends a section by
hand. There is nothing to regenerate — the conflict is authored churn on an
index whose content is derivable from the directory listing beside it.

**F6 — two generated paths are still routed to a human decision.** The 50-session
measurement found `docs/decisions/INDEX.md` in **4 distinct sessions** and
`dist/router.json` in 1. Neither is matched by `sync_pr_branch.ts`'s `GENERATED`
list: the first is written by `src/scripts/adr/regenerate_index.ts` with a
dynamic directory argument (so the literal never appears in a grep and was
missed), and the second sits under `dist/` while the list carries only the
`dist/agent-src/` prefix. Both have exactly one correct resolution —
regenerate — and the tool currently says "make a human decision", which is the
same defect the list's own comment already records once for
`src/scripts/hook_manifest.json`.

## Council verdict (2026-08-21, 2 seats + blind peer review, $0.12)

Convergent, both seats:

1. **Ship the dashboard cutover repository-local only, and NOT as
   "absent = PASS".** An unconditional pass on absence silently changes what
   `--check` means and cannot tell a correctly-untracked repository from a broken
   generator. Both seats required an **explicit mode** instead, with this table:

   ```
   tracked mode:    absent → fail · present+stale → fail · present+current → pass
   untracked mode:  tracked in git → fail (print `git rm --cached`) ·
                    absent → pass · present+stale → fail · present+current → pass
   ```

   Untracked must not mean unchecked: a *present* local dashboard is still
   verified for freshness.

2. **Do NOT distribute the ignore entry to consumers in this PR.** A
   tracked→untracked transition **cannot be made atomic across independently
   versioned consumer repositories** — package code, copied workflow templates,
   `.gitignore` and the git index do not update together. This is the answer to
   the version-skew question too: the skew does **not** close by itself, and a
   guard placed in a *new* template cannot repair a consumer still running an
   *old* copied one.

3. **Do NOT invert the shipped consumer workflow to fail-if-tracked.**
   "Not tracked" is a migration check, not a correctness check — once untracked
   it proves neither that generation succeeds nor that the view is current.

4. **Q5 option (ii) for the stubs index — stop appending.** The stub files are
   the authoritative inventory; the README keeps its criteria prose. Option (i),
   generating the table, would introduce a schema, a generator, an ordering
   policy and a staleness contract to recreate a redundant index. Precondition
   both seats named: migrate any information unique to a README section into the
   corresponding stub *first*, and check section anchors for inbound links
   before deleting.

5. **Q3 — the estate-budget history split — is REFUSED in the shape proposed,
   and this was both seats' hardest pushback.** Extracting `baseline_history`
   into per-record files is not blocked by that record's line-merge prohibition, but
   selecting the record **lexicographically newest** is unsafe: branch A lowers
   the baseline recording justification A, branch B appends a later-sorting
   record for a different change, the files merge with no conflict, and the gate
   validates A's lowering using B's justification. The `why` *authorises* a
   baseline lowering, so this is a silent authorisation failure that passes
   review and CI. The endorsed shape is an **explicit immutable record
   reference** from the budget (`"lowering_reason_record": "<id>"`) plus a
   concurrent-branch integration test proving the reader cannot validate one
   transition using another's record. Separate PR.

6. **Q4 — the gate-violation baselines stay blocked.** No cheaper safe append
   transformation exists for the active keyed dict; `{count, landed, note}` must
   stay together until the gate-independence / measurement-epoch question
   that record noted is answered. The conflict there is preserving a meaningful
   concurrency boundary.

7. **The `sync_pr_branch.ts` compatibility retirement criterion must be a
   defined support window, not "one release".** Raised by one seat, endorsed in
   peer review as the weakest part of the plan.

Recorded divergence: one seat proposed usage telemetry to set the retirement
criterion; the other refused it as inappropriate for a drop-in developer tool
and asked for a declared support window plus a fixture matrix instead. **The
declared-window option is taken** — this repository has no telemetry consent
model for consumer state, and a window is checkable without one.
