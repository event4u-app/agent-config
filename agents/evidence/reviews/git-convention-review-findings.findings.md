| 1 | high | src/scripts/sync_pr_branch.ts:697 | `mergePinned` reads any staged difference after a failed merge as "this merge half-applied it" and tells the user to run `git reset --merge`. The premise ("git only starts a merge from an index that matches HEAD") is not checked: the index is never snapshotted before the merge, and the dirty-tree refusal the header documents (exit 1 "git refusing the merge before it starts") arrives exactly when the user has staged work. A non-fast-forward merge refused because of pre-existing staged changes therefore prints the half-applied message and a remedy that resets those staged entries, discarding the user's work. Snapshot `git diff --cached --quiet` before the merge and only attribute a staged difference to the merge when the index was clean beforehand. | open | |
| 2 | medium | src/scripts/sync_pr_branch.ts:614 | The policy-moved check (`checkPin`) runs only on attempt 1 of `integrateWithPinnedBase`. The comment's reason (a "nothing was merged" stop would misreport) argues for a different message on retry, not for skipping the check. | open | |
