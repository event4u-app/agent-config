## What the change does

The branch implements phases 1 and 2 of a roadmap whose goal is: a dispatched subagent receives a bounded set of memory references cut for its audience, and what a subagent writes back carries who wrote it.

1. **Audience table** (`subagent-spawn-contract.md`): one memory cut per spawn audience — orchestrator, non-fork, fork, judge-seat, unpaid, cheap-paid. The council skill cites the judge-seat row. Implementer prompt templates gain a `{{knowledge_refs}}` slot labelled as leads; judge, candidate, debate and skeptic templates carry none (a test pins both).
2. **Writer provenance** (`memory_signal.ts`, both twins): a record carries `writer` and `taint` when handed them; a line without a writer reads `unknown`; a writer whose class is `unpaid`, `council-seat` or `judge-seat` is refused before anything is written. `learning_sidecar.readSignals` skips a record tainted `external_read`, so it never corroborates a lesson.
3. **The gated part — a new hook concern `memory-audience-shadow`**, bound on claude `pre_tool_use` only, tools `[Agent, Task, Write, Edit, MultiEdit]`, `severity: advisory`, `effect: telemetry`, `fail_closed: false`, `needs_payload_bodies: [input]`, `payload_fields: [prompt, file_path, path]`.

   - An Agent/Task call without `agent_id` appends one `memory_slice_shadow` line: the count of curated `agents/memory/*.{yml,yaml,md,json}` paths the prompt names (intake excluded), capped at the spawn contract's 5, the number dropped by the cap, and an estimated token count from file sizes.    - Every path exits 0 and writes nothing to stdout. The prompt is read in memory; no path, agent id or prompt text is written.
