# Round 2 Review

## 1. Agreement with prior reviewers

**I fully agree with Reviewer B's core finding** (and Reviewer A's related MEDIUM point): The implementation validates only path existence, not whether the ruling authorizes this specific bypass.

**Evidence**: Line 601 wires `rulingCommitted` as `(rel) => index.has(rel)`. This accepts any committed file under `agents/evidence/owner-directives/`, regardless of content. A ruling about bypass X can close the record for bypass Y.

**I agree with Reviewer A's MEDIUM point on ruling content validation** for the same reason—it's the same defect stated differently.

**I partially agree with Reviewer A's HIGH point on `bypass_mode: always`**: The contract explicitly forbids closing such bypasses with a ruling, but I see no enforcement. However, this may be caught by separate actor validation outside this diff's scope. Needs verification against full source.

**I disagree with Reviewer A's MEDIUM point on ruling temporal validation**: The check `rulingCommitted(ruling)` uses `committedEvidence(root)`, which should verify the file exists in HEAD (not historical commits). This satisfies "must be committed at HEAD." The contract doesn't require the ruling to postdate `restore_by`—only that it exist when the check runs.

## 2. Disagreements

**Reviewer A's temporal validation concern**: The contract doesn't state the ruling must be committed "at or after `restore_by`". It says the ruling "must be committed at `HEAD`", which `committedEvidence` should enforce. The timing requirement applies to council reviews (line 1254-1255), not rulings.

**Reviewer A's LOW point on regex strictness**: I agree this is truly low-priority. The `committedEvidence` check prevents non-existent files regardless of filename edge cases.

## 3. New findings

### CRITICAL: Ruling unbounded to bypass subject

**File**: `src/scripts/_lib/platform_anchor.ts`, line 1249  
**Extends**: Reviewer B's finding

**Why this matters beyond what was stated**: The contract says a ruling closes the restore half "when the owner keeps the bypass standing." But "the bypass" is singular and specific. The implementation allows:

```
# Record A (subject: abc123...)
restored_at: superseded-by-owner-ruling agents/evidence/owner-directives/ruling-for-X.md

# Record B (subject: def456...)  
restored_at: superseded-by-owner-ruling agents/evidence/owner-directives/ruling-for-X.md
```

Both records close on the same ruling file, which structurally cannot authorize both subjects unless it's a blanket "keep all bypasses standing" directive—which the contract doesn't envision.

**Fix**: Replace `rulingCommitted: (rel: string) => boolean` with:
```typescript
rulingCovers: (rel: string, subject: string) => boolean
```

Parse the ruling, verify it contains the bypass `subject` digest, and explicitly states "keep standing" for that specific bypass.

### MEDIUM: Malformed ruling path silently continues

**File**: `src/scripts/_lib/platform_anchor.ts`, line 1269

**Issue**: If `ruling !== null` (regex matched) but `rulingCommitted(ruling)` returns false (file doesn't exist), the code sets a malformed finding at line 1249-1250. But then at line 1265, the check is:

```typescript
if (ruling !== null) {
    // overdue review check
    continue;
}
```

This `continue` fires even when the ruling failed validation. The record is not reported as unrestored, despite having an invalid ruling reference.

**Expected**: The `continue` should only fire after ALL ruling validations pass. Invalid ruling → fall through to standard unrestored checks.

### LOW: Council review temporal check incomplete

**File**: `src/scripts/_lib/platform_anchor.ts`, line 1254

The check `reviewCovers(review, subject, time)` ensures the review was committed at or after the bypass `time`. But for a ruling-closed record, the contract says review is "overdue seven days after `restore_by`". The code checks this at line 1266-1273 for overdue, but doesn't verify the review (if present) is committed at or after `restore_by` (not just `time`).

This is minor because `restore_by >= time` by construction, so checking `time` is stricter. But it's semantically inconsistent with the contract language.

## Summary

**Severity**: One CRITICAL defect (ruling unbounded to subject), one MEDIUM defect (malformed ruling bypasses enforcement), two LOW observations.

**Checked**:
- ✅ Fail-closed for missing files, wrong format
- ✅ Overdue review enforcement preserved
- ✅ Path traversal prevented by regex structure
- ❌ **Ruling content not validated against bypass subject**
- ❌ **Malformed ruling doesn't fall through to unrestored check**
- ⚠️ Cannot verify `bypass_mode: always` handling from diff

**Recommendation**: The core concept is sound, but the validation is insufficient. Needs content-aware ruling verification before merge.
