# The no-runtime surface census: 131 files, six active blockers, all six dispositioned

**Base commit:** `5e2fe269cc8985af0e7eabc8d351ce895b904970`
**Measured:** 2026-08-27, discharging steps 4.2 and 4.2b of
`road-to-runtime-governance-flip`.

**This is the second version. The first was REJECTED by the second reader, and
the rejection was right** — it found three active blockers the first pass had
buried. § Second-reader review has the whole exchange, because the reason the
number moved from 3 to 6 is the most useful thing in this document.

The sum is the re-run count, never the authoring-time 129.

`not-reopened`, `derivative` and `reversal/meta` are sub-classes of *historical*
and *incidental* respectively, kept separate because collapsing them loses the
distinction that matters most: **an agent-memory prohibition is not a resident-process
prohibition**, and folding the five P3 entries into "historical" would read as
though this reversal touched them. It does not.

## The classification rule, from Phase 0.3

> **Active** — the artefact, read literally by an agent or a gate, **refuses an
> action this reversal permits**.
> **Historical** — it describes the old state and refuses nothing.
> **Incidental** — "runtime" means something else.

## Second-reader review — REJECTED, then fixed

Step 4.2b requires that "a second reader has approved the non-blocker
classifications — so an active blocker cannot be retired by relabelling it
alone." An AI council was that reader (2026-08-27, `anthropic` + `openai`, both
present; subscription transport, nothing billed).

**Verdict: split. One seat APPROVED with a clarification; one seat REJECTED.**
The rejection is upheld, on evidence rather than on a count of votes.

The first version classified 82 of the 131 by **artefact class** rather than by
reading them — the argument being that a skill, a command, a config comment or an
archived doc *cannot refuse an action a contract permits*, because it has no
normative force. The rejecting seat answered:

> The census defines "active" as refusal "by an agent or a gate", yet its "honest
> weakness" substitutes **formal authority for operational effect**. `src/skills/`
> and injected contexts can directly instruct agents … Therefore, file location
> alone cannot prove non-blocker status.

**That is correct, and this change contains its own counterexample.**
`src/agent-src/contexts/execution/subagent-steering.md:107` read
`A CONFIG PACKAGE RUNS NO DAEMON.` — inside an all-caps instruction block, in a
projected context file an agent loads and obeys. It is an operational refusal in
exactly the class the rule declared incapable of one. Phase 0's five-class read
set (rules, contracts, schemas, gates, accepted ADRs) **omitted
`src/agent-src/contexts/` entirely**.

So the 28 files in the operationally-loaded classes — `src/agent-src/`,
`src/skills/`, `src/domains/`, `src/config/` — were read **line by line**. That
read found **three further active blockers**:

| Found by | Artefact | What it was |
|---|---|---|
| the roadmap, in step 4.3 | `src/agent-src/contexts/execution/subagent-steering.md:107` | an all-caps instruction block; the roadmap already knew, but Phase 0's class list did not |
| **the second reader's objection** | `src/skills/verify-repair-loop/SKILL.md:140` | item 5 of a numbered *"Before finalizing, confirm:"* checklist — **"No daemon / persistent runtime introduced."** An agent running that checklist would refuse the change |
| **the same read** | `src/domains/engineering-base/mission/upgrade/command.md:125` | a live instruction to follow `no-runtime-boundary` *"exactly as"* written — pointing at a now-superseded contract |

The other seat's approval rested on "rules are the normative layer and Phase 0
read all rules". True and insufficient: only two rules matched, and the layer
that actually carried a refusal was **contexts**, which no rule mediates.

**What did not change:** neither seat challenged the three original active
dispositions, and both agreed `derivative` and `not-reopened` belong under
*historical* rather than *active* — "becoming false is not itself operational
refusal". The rejecting seat also asked for the nine self-authored files to stop
being called `incidental`, since they discuss the same runtime boundary rather
than another sense of the word. Adopted: they are now `reversal/meta`.

**The residual weakness, stated:** 103 files are still classified by class —
`docs/decisions/`, `docs/contracts/`, `src/rules/`, `src/scripts/`,
`docs/archive/` and docs prose. Those five classes **were** read individually in
Phase 0 (49 files) or are archived by construction. What remains unread is docs
prose that no mechanism loads. That is a narrower claim than the first version
made, and it is the one the evidence supports.
