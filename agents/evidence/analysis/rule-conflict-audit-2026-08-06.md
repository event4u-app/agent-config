This run generates candidates at the full-recall operating point (same-axis opposing poles, no co-fire filter) and gives every candidate a written disposition.

## 2. Real-conflict findings (act on these)

**12 findings.** These are pairs that fire on a shared, plausible situation with contradictory mandates, and neither rule (nor `rule-interactions.yml`) names or resolves the collision.

### RC-1. `commit-policy` × `secret-vcs-guard`

- **Generated by:** `axis2:ask-vs-dont-ask`
- **Finding:** commit-policy.md:17-18 "NEVER COMMIT. NEVER ASK ABOUT COMMITTING. EXCEPTIONS ARE EXPLICIT, NOT INFERRED." vs secret-vcs-guard.md:45-47 "...WITHOUT STOPPING FIRST. DETECT -> SHOW THE MATCH -> ASK -> OFFER ALTERNATIVES. NEVER SILENTLY COMMIT A SECRET." Situation: agent is about to run `git commit` (one of commit-policy's 4 authorized paths already cleared) and the diff contains a credential. secret-vcs-guard demands STOPPING the commit and ASKING how to handle the secret; commit-policy's exception list is closed ("not inferred") and does not name secrets as a 5th exception, nor does non-destructive-by-default's Hard-Floor trigger table (production-branch merge / deploy / push / prod-data / bulk-deletion / infra-diff / irreversible-external-action) list "diff contains a credential" as a row. Neither rule cross-references the other.

### RC-2. `communication-through-line` × `role-mode-adherence`

- **Generated by:** `axis4:reply-closing`
- **Finding:** communication-through-line.md:21 "CLOSE THE LOOP WITH ONE END-SUMMARY. NEVER MAKE THE USER RE-DERIVE WHERE THINGS STAND." (restates direct-answers' single end-summary as the reply's closing content) vs role-mode-adherence.md:28-31 "2. End with the structured mode marker: <!-- role-mode: <active_role> | contract: <kebab-case-fields> -->". Situation: `roles.active_role` is set AND the reply is a work reply that must close with an end-summary. Both Iron Laws claim the terminal position of the reply; neither rule names or subordinates to the other.

## 4. Methods note (reproducibility)

Generator: `generate_candidates.py`. Adjudication table: `adjudications.py`. Assembly: `build_report.py` + `render_report.py`. Raw candidate list: `candidates.csv`. Full disposition table (all 192, machine-readable): `dispositions.csv`.

**Operating point:** same-axis opposing poles, no co-fire filter (per task spec — filtering by keyword/co-fire overlap was already shown to destroy recall in the prior static-detector work).

**Tag assignment:** hand-curated by reading each candidate rule's Iron Law block and body (not pure regex — a leaky regex was the documented failure mode of the earlier static detector). The tag lists themselves ARE the detector; they are fully enumerated in `generate_candidates.py` so the run is mechanically reproducible from that file alone.

**Axis 1 (act-vs-read):** ACT pole = 4 rules (`context-hygiene`, `active-remediation`, `output-discipline`, `roadmap-progress-sync`). READ pole = 10 rules (`think-before-action`, `source-discovery-gate`, `security-sensitive-stop`, `external-reference-deep-dive`, `improve-before-implement`, `invite-challenge`, `notes-first-reasoning`, `question-not-instruction`, `cross-source-consistency`, `minimal-safe-diff`). Cross-product = 40 hits.

**Axis 2 (ask-vs-dont-ask):** ASK pole = 7 rules (`ask-when-uncertain`, `invite-challenge`, `cross-source-consistency`, `missing-tool-handling`, `secret-vcs-guard`, `decision-revisit-gate`, `linked-projects-onboarding-gate`). DONT-ASK pole = 4 rules (`no-cheap-questions`, `commit-policy`, `autonomous-execution`, `scope-control`). Cross-product = 28 hits.

**Axis 3 (broaden-vs-narrow):** BROADEN pole = 7 rules (`downstream-changes`, `broken-access-control`, `history-discipline`, `scale-discipline`, `senior-engineering-discipline`, `active-remediation`, `domain-safety-pii`). NARROW pole = 5 rules (`minimal-safe-diff`, `scope-control`, `roadmap-ci-steps-policy`, `content-quoting-floor`, `code-comment-discipline`). Cross-product = 35 hits.

**Axis 4 (absolute-vs-absolute):** 5 same-surface clusters, all internal pairs (`C(n,2)`) generated as candidates (not opposing poles — this axis groups by *subject*, not by mandate direction): `reply-closing` (8 rules → 28 pairs: `direct-answers`, `session-canary`, `role-mode-adherence`, `fast-path-marker-visibility`, `communication-through-line`, `user-interaction`, `language-and-tone`, `telegraph-speak`); `commit-git-authority` (6 rules → 15 pairs); `ask-authority` (5 rules → 10 pairs); `verification-authority` (5 rules → 10 pairs); `security-stop-authority` (5 rules → 10 pairs). Total = 73 hits.

**Axis 5 (effort-vs-coverage):** EFFORT pole = 5 rules (`token-efficiency`, `autonomous-execution`, `context-hygiene`, `roadmap-ci-steps-policy`, `content-quoting-floor`). COVERAGE pole = 7 rules (`downstream-changes`, `broken-access-control`, `scale-discipline`, `history-discipline`, `roadmap-progress-sync`, `senior-engineering-discipline`, `active-remediation`). Cross-product = 35 hits.

211 raw axis hits → 192 unique pairs after global dedup (a pair can be nominated by more than one axis, e.g. `ask-when-uncertain`×`no-cheap-questions` is both axis2 and axis4:ask-authority).

**Adjudication:** every one of the 192 unique pairs was read against the actual rule text (Iron Law + body + See-also), against `docs/contracts/rule-interactions.yml`, and against each other's cross-references, then assigned exactly one disposition by hand. No keyword-overlap or co-fire filter was applied at generation time — precision is entirely a product of the adjudication pass, per the agreed method.
