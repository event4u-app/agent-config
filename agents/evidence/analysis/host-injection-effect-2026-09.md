## The two columns, and why neither is the other

**Slots bound** is computed and cheap. **Body reaches the model** is observed and
expensive, and owner ruling E3 admits a host to `lean_projection.hosts` on the second
only: one transcript in which a model visibly acts on a delivered body. Documentation
of a host's hook API is not admission.

`cowork` is why the distinction is not pedantry: **eight slots bound, and measured
`observed-false`** — its trampoline discards dispatcher output and exits 0. A table
with only the binding column would admit it.

## Why each row reads as it does

- **`augment`** — Binds five slots and does not honour a deny (docs/enforcement-by-host.md). It also has no `user_prompt_submit` slot, which is a DECLARED gap in the manifest rather than an oversight, so the delivery path this record measures does not exist there today.
- **`claude`** — The delivery mechanism is measured for EQUIVALENCE (579/579 then 616/616 byte-equal deliveries, docs/CLAIMS.md) and for cost, and neither is what E3 asks for. E3 wants one transcript in which the model VISIBLY ACTS on a delivered body, and no such transcript exists: `lean_projection.mode` resolved to `eager-all` for the whole recorded history, so the concern emitted zero bytes in every session on record. Recording `observed-true` from the byte-equality measurement would be exactly the documentation-is-not-admission move K1 forbids, one layer in.
- **`cline`** — Binds `user_prompt_submit` (hook_manifest.yaml:1315) with a `.md` rule tree, same shape as Cursor and the same unmeasured question. `rule-inject` is absent from its concern list.
- **`codex`** — No platform key in hook_manifest.yaml at all, so no slot is bound and no concern can fire. Same distinction as copilot: the absence of a binding is a computable fact and is not the observation E3 asks for.
- **`copilot`** — `fallback_only` with zero slots bound: this package binds nothing there, so there is no hook stdout to reach anything. Recorded as unobserved rather than `observed-false`, because nobody has looked — a structural argument that it cannot work is still not an observation that it does not.
- **`cowork`** — The one host E3 excludes by an existing measurement rather than by absence of one: its trampoline discards dispatcher output and exits 0, so a delivered body cannot reach the model however many slots are bound. Eight slots bound and zero effect is precisely why `emits` and `injection_effect` are separate axes in this record. CITATION LIMIT, stated rather than smoothed over: the host version was not captured when that observation was made, so this row does not meet the four-part protocol in full and its `host_version` says so instead of inventing one.
- **`cursor`** — Binds `beforeSubmitPrompt` onto `user_prompt_submit` (hook_manifest.yaml:1300, alias :1407) and carries a `.md` rule tree, which makes it the strongest candidate — and the binding is not the question. Whether Cursor adds hook stdout to the model's context is unmeasured, and cannot be measured from a Claude Code session. `rule-inject` is absent from its concern list, so nothing would be emitted there today in any case.
- **`gemini`** — Five slots bound, no `pre_tool_use` binding, and no session available to observe from. Recorded as unobserved rather than assumed either way.
- **`windsurf`** — Three slots bound and no tool-lifecycle surface at all (docs/enforcement-by-host.md). Not observed, and not reachable from a Claude Code session.

## `cursor.md_tree_loaded` (step 1.3)

Both trees are written today (condense.ts writes the symlink tree in the TOOL_DIRS loop and `_emit_cursor_mdc` writes the .mdc companions), so a double carry is possible by construction and unobserved in fact. It cannot be observed from a Claude Code session, and K4 forbids removing the .md bodies before it is. Carried under an underscore key because it is a property of a TREE rather than a host verdict, and putting it in the host namespace would make `cursor` answer two different questions.

## What this census does NOT do

It computes no verdict. Admission under E3 is a one-line read of the observed column
and is applied by whatever would change a projection, never here — a report that also
decided admission would be the one place an inference could quietly replace an
observation.

`unobserved` is a RESULT, not a gap: the host keeps its full rule bodies and loses
nothing while it waits, which is the roadmap's K6 and is asserted per PR by
`check_host_tree_parity` in the predecessor.
