# Claude Code hook + agent parity — Phase 0 findings (road-to-claude-code-single-surface)

Date: 2026-07-07. Evidence gate for retiring the marketplace plugin as a
content surface (council 2026-07-07, Option B). **Verdict: parity CONFIRMED —
proceed with plugin retirement as written; thin-plugin fallback not needed.**

## 1. Plugin hook matrix (inventory)

Source of truth: `hooks/hooks.json` at the repo/plugin root, **generated by
`src/scripts/condense.ts`** (emits "Generated hooks/hooks.json (N Claude
plugin hooks)"); runtime concern wiring lives in
`src/scripts/hook_manifest.yaml` and is resolved per event by
`agent-config dispatch:hook`.

Six events, all with the identical command shape (project shim →
global-binary fallback, per ADR-020):

| Native event | dispatched as |
|---|---|
| SessionStart | `session_start` |
| SessionEnd | `session_end` |
| Stop | `stop` |
| UserPromptSubmit | `user_prompt_submit` |
| PreToolUse | `pre_tool_use` |
| PostToolUse | `post_tool_use` |

Command template: `BIN="$CLAUDE_PROJECT_DIR/agent-config"; [ -x "$BIN" ] ||
BIN=agent-config; "$BIN" dispatch:hook --platform claude --event <event>
--native-event <Native> --project-dir "$CLAUDE_PROJECT_DIR" --min-version 1`.
No matchers, no timeouts, no env-injection fields — the simplest schema case.

## 2. Empirical firing test — settings.json hooks, plugin not involved

Scratch project with the six-event matrix registered ONLY in
`.claude/settings.json` (marker-file commands), exercised via headless
`claude -p` with one Bash tool call. Result: **all six markers written,
exactly once each** (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse,
Stop, SessionEnd). Settings-registered hooks are fully functional without
the plugin.

## 3. Schema + coexistence (official docs, code.claude.com/docs/en/hooks)

- The hook schema is **identical** across plugin `hooks/hooks.json`,
  `~/.claude/settings.json`, `.claude/settings.json`, and
  `settings.local.json`. No plugin-exclusive fields exist (no special env
  injection, no `continueOnError`); settings hooks additionally support
  `timeout`, `matcher`, `if`, `async` etc. — a superset of what our matrix
  needs.
- **All sources fire in parallel**; identical handlers are deduplicated by
  command string. Consequences: (a) user-owned hooks on the same event
  coexist with our managed entries by design; (b) during a migration window
  where BOTH the plugin and the managed settings block carry the same
  dispatch command, Claude Code dedupes them — no double-firing.

## 4. Subagent parity (official docs, code.claude.com/docs/en/sub-agents)

- `~/.claude/agents/` (user scope) and `.claude/agents/` (project scope) are
  first-class, scanned recursively; same frontmatter format as plugin agents.
- Plugin agents are **more restricted**, not less: `hooks`, `mcpServers`,
  and `permissionMode` frontmatter are ignored when loaded from a plugin.
- Precedence: project > user > plugin on name collisions. Naming changes
  from `agent-config:<name>` (plugin-scoped id) to plain `<name>` — the
  projection should keep stable file names to keep @-mention muscle memory.
- Caveat for the installer: a running session does not detect a **newly
  created** `~/.claude/agents/` directory — first install of the agents dir
  requires a session restart (document in migration notes).

## 5. Decision

Parity confirmed on both axes → **Phases 1–4 proceed as written** (managed
settings-merge block, installer wiring, plugin retirement, guardrails). The
thin-plugin fallback (hooks-only plugin) is not required. Recorded per the
roadmap's Phase 0 checkpoint; council convergence inlined in the roadmap
Context section.
