## Method

- **L-1**: `jscpd internal/bench/provenance/samples --min-tokens <N>`. `min-tokens`
  is jscpd's one documented sensitivity knob; a **pre-declared sweep**
  (30/25/20/15/12/10) was run and **all results are reported below** — the
  shipping value is chosen by the FP constraint, not by maximizing recall.
- **L0**: `scanoss-py scan internal/bench/provenance/samples` (real KB, WFP
  fingerprints only leave the machine — principle 7 holds).
- A sample counts as detected if it appears in any clone pair (L-1) or returns
  a non-`none` match id (L0).

L0 hits are TS-only (0/12 PHP samples matched). Both L0 false positives are

## Verdict against the four pre-registered criteria

1. **v+r recall ≥ 10/16** — L-1 `10/16` (exactly at floor), UNION `12/16` → **PASS**.
2. **FP ≤ 1/12** — L-1 `0/12` PASS, but L0 `2/12` and UNION `2/12` → **FAIL**.
3. **rename-only MUST hit (principle 6)** — L-1 `4/8`, L0 `0/8`, UNION `4/8` → **FAIL**.
4. **full seeded ≥ 21/24 ⇒ drop Phase 5** — UNION `18/24` → threshold not
   reached, so **Phase 5 is NOT auto-dropped**; the residual class is real.

**G0 = THRESHOLDS MISSED (criteria 2 and 3).** No silent adjustment: the
numbers stand as measured.

## The load-bearing finding: principle 6 is refuted as written

The roadmap asserts (principle 6): *"Winnowing normalizes away
identifiers/whitespace by construction — a snippet hit cannot be cleared by
renaming variables."* Measured: SCANOSS rename-only recall is **0/8**, jscpd's
is **4/8**. Neither layer delivers the anti-launder-by-rename guarantee at
these snippet sizes. Since S2.2's clearing protocol was designed *on top of*
that guarantee, the guarantee must be re-derived from measurement, not
asserted from the tool's description.

## Honest scope bounds

- The corpus is **synthetic-canonical** (S0.1): no sample is indexed in any
  KB, so **L0 recall here is not a valid measure of L0's real-world recall** —
  it is contaminated exactly as the pre-registration predicted. What L0's run
  *does* validly measure is its **false-positive behaviour on real KB**
  (2/12), because those matches are real KB matches against code we wrote
  ourselves.
- L-1's numbers are fully valid: jscpd is self-contained and needs no KB.
- n is small (8 per depth); single machine, single day.
