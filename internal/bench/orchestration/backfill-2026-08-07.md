## The capture-rate finding

Two roadmaps have been blocked for a month on *"≥20 orchestration lines in the
current month"*, with the stated remedy **"use the agent on real delegable
work"**.

The agent was used on real delegable work **370 times**. The model-carried
`orchestration_record` step captured **1** of them — a capture rate of
**0.27%**. The current month's audit file did not exist at all.

The blocker was never a usage problem. It was an instrumentation defect, and
the remedy it prescribed could not have resolved it: a model-carried emit step
that fires 0.27% of the time does not reach 20 lines by being asked to try
harder. This is the argument for moving the emit into a `SubagentStop` concern
(Phase 4), and it is measured rather than asserted.

## The coverage limit, stated because it bounds everything below

Only **synchronous** dispatches carry cost. An asynchronous dispatch returns a
launch acknowledgement (`isAsync: true`, `status: "async_launched"`) and its
completion never writes `totalTokens` back into the parent transcript. 326 of
370 dispatches are async.

So the measured population is **39**, not 370. Emitting 370 lines of which 331
carry a null cost would have cleared the ≥20 gate on a count the data does not
support. The extractor reports both numbers for that reason.

**27 of 39 metric-bearing dispatches resolved to an Opus tier.** The
project-local settings comment states the cost thesis as *"auto-dispatch
delegable high-volume / low-difficulty slices to the cheaper tier (`downshift:
true` is already the default)"*. Measured, downshift did not happen: the
dominant resolved model is the expensive tier, and the cheapest tier appears
once in 39 dispatches.

This is orthogonal to whether delegation is worth doing — it says the
mechanism the cost thesis rests on was not operating during the observation
window. `subagents.downshift` is a documented setting with a reference
implementation (`resolveSubagentRouting`) that has **zero production callers**;
tier selection during this window was model-carried, and it selected up.

## What this file deliberately does not contain

A `token_delta`. The in-session counterfactual — what these 39 tasks would have
cost had the main agent done them itself — is not on disk and is not measured
by anything. Computing one here and stamping it `measured` is the laundering
claim criterion (2) forbids. The orchestrated side is measured; any comparison
must name its own baseline method and carry `estimated`.

Phase 2 gates the claim against these numbers.
