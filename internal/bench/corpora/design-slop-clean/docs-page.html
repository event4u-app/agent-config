Retrying a charge safely

A network timeout does not tell you whether the charge was created. Send an idempotency key so a retry cannot create a second charge.

Idempotency keys

Pass any string up to 255 characters in the Idempotency-Key header. A UUID version 4 is a reasonable default. Generate it before the first attempt, not per retry. 

curl https://api.example.com/v2/charges \
  -H "Idempotency-Key: 8f14e45f-ea0c-4b9a-9b1d-2f6c7a30dd11" \
  -H "Content-Type: application/json" \
  -d '{"amount": 4200, "currency": "EUR", "source": "src_18f2"}'

Key lifetime

We store the first response for 24 hours. A replay inside that window returns the stored response with Idempotent-Replay: true. After 24 hours the key is forgotten and a replay creates a new charge.

Conflicting replays

Reusing a key with a different request body returns 409 idempotency_key_reuse. The original charge is untouched. This usually means the key was derived from something too coarse, such as a user id rather than a cart id.

StatusMeaning
200Stored response replayed
201Charge created on this request
409Key reused with a different body
