## Carrier grade — exactly one per host, read off the manifest

Grades are defined in `internal/bench/frontend-power-PREREG.md` § Carrier
grades. They come from `src/scripts/hook_manifest.yaml` `platforms:` rows plus
`VERIFIED_PLATFORMS`, never from the host's name. Enumerated by walking the
`platforms:` block in this session:

| Host | pre_tool_use | post_tool_use | stop | Grade |
|---|---|---|---|---|
| `claude` | `:960` | `:961` | `:958` | **A** |
| `augment` | `:952` | `:953` | `:951` | **B** |
| `cowork` | `:1014` | `:1015` | `:1012` | **B** |
| `cursor` | absent | `:1038` | `:1036` | **B** |
| `cline` | absent | `:1053` | `:1051` | **B** |
| `gemini` | absent | `:1089` | `:1087` | **B** |
| `windsurf` | absent | absent | `:1069` | **B** |
| `copilot` | absent | absent | absent | **C** |

`claude` is Grade A because it is the sole member of `VERIFIED_PLATFORMS`
(`src/scripts/hooks/host_semantics.ts`) — bound *and* honours a deny.
`augment` and `cowork` are bound and ignored: both trampolines discard
dispatcher output and `exit 0`. `copilot` is the only Grade C, confirmed by
execution: `agent-config hooks:status` prints `degraded: rule-only fallback —
hooks are not auto-firing on this platform`.

**This corrects the parent roadmap.** Its `b-hook-slot-on-windsurf` blocker
records windsurf as "Grade C: static delivery only" on the premise that it has
no `post_tool_use` surface. The premise is true and the conclusion is not:
windsurf carries `stop` at `:1069`, with five concerns already bound there, and
steps E1.2 and E1.3 are `stop`-slot carriers. Windsurf is Grade B.

## Routing — measured

Predicate: `isUiPath(p) || isUiTreePath(p)` from `src/scripts/_lib/ui_surface.ts`.
The `||` is the contract's own semantics (`:88-91`: "callers that need the
narrower answer combine this with `isUiPath`"); an `AND` reading was tried first
in this session and returned 5 of 23, which measured the corpus's directory
layout rather than the predicate.

| id | metric | baseline |
|---|---|--:|
| M-R1 | frontend recall (cases with ≥1 detected UI file) | **20 / 23 = 87.0 %** |
| M-R2 | backend false positives | **0 / 7 non-UI files** |
| M-R3 | surface-mode accuracy | not obtainable — no resolver exists to produce a value |
| M-R4 | change-intent accuracy | not obtainable — same reason |
| M-R5 | trivial-lane FP/FN | not obtainable — the allow-list is prose in two rules, with no decidable implementation to score |

**The three M-R1 misses are the finding, not noise.** They are `greenfield`
(only `.gitkeep`), `supplied-finished-comp` (only `HANDOVER.md`) and `wireframe`
(only `wireframe.md`). In all three the *request* is a UI request and no UI
**file** exists yet.

```
ui_surface IS A PATH PREDICATE. A UI INTENT THAT HAS NOT YET PRODUCED A FILE
IS INVISIBLE TO IT. SO A PRE-WRITE GATE KEYED ON THIS PREDICATE CANNOT FIRE ON
THE FIRST WRITE OF A NEW SURFACE — WHICH IS EXACTLY THE WRITE IT MOST WANTS.
```

That asymmetry is why E1.1 is a `post_tool_use` carrier rather than a
pre-write one: after the write, the file exists and the predicate answers.
It also bounds E2.2 honestly: an audit-before-write gate on a greenfield surface
has no path to key on until the surface exists.

M-R2 = 0 is a real zero, not an unmeasured one. The pinned negative
(`full-stack-feature-with-ui/pages/api/reports/export.ts`) is excluded twice
over: `.ts` is not in `UI_EXTENSIONS`, and `pages/api/` is in
`UI_TREE_EXCLUSIONS`.
