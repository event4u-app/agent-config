## How pre-registered this registration actually is — the honest limit

No free-route answer, no paid answer and no verifier reading of any kind existed
when this file was written. The loopback stubs the harness tests run against are
not readings: they answer from a fixed script. The one prior observation about
the route is non-numeric and is the reason for the pacing rule below: the
keyless route allows one anonymous request per 30 s per IP (council decision 2,
round 1). No bar below was placed near any observed value, because there is
none.

## Label — `manufactured`

Every row this window produces is **manufactured**: the asks are generated by
the harness over a sampled corpus, not drawn from organic work. The evidence
file reports it under that label, and no reader may pool its rows with organic
rung-0.5 traffic. A flip that rests on this window says so in its claim line.

## Corpus — frozen at the commit that adds this file

**Reference.** The corpus is read from the tree at the commit that last touched
this file (`git log -1 --format=%H -- internal/bench/free-hands-shadow-PREREG.md`),
through `git ls-tree` and `git cat-file`, never from the working tree. Every file
is a tracked file of this public repository, so every payload is
`public-artifact` (decision A10: every free route stays at that ceiling). A
later edit to this file moves the reference and is a new registration.

**Seed.** `20261022`, through `mulberry32`; candidate lists are sorted by path
before a Fisher–Yates shuffle, so the sample depends on the seed and the tree
only. The audit sample uses seed `20261023`.

**Payload survival filter.** A sampled item is kept only when the production
payload builder (`buildHandPayload`, with the project's linking identifiers and
an identifier-protecting egress scope) leaves the item's ground truth — the
path for `classify`, the field value for `extract` — byte-identical in the
payload. An item whose answer a placeholder would hide is replaced by the next
item in shuffled order, never sent. The kept list is digested into the run
ledger's header on the first call; a resumed run whose recomputed digest differs
refuses to continue.

### `classify` — the artefact class of a tracked file

Closed label set of nine, each defined by a disjoint path rule:

| Label | Path rule |
|---|---|
| `skill` | `src/skills/<name>/SKILL.md` |
| `rule` | `src/rules/<name>.md` |
| `command` | `src/domains/**/command.md` or `src/agent-src/commands/**.md` |
| `adr` | `docs/decisions/ADR-<n>*.md` |
| `roadmap` | `agents/roadmaps/**.md` |
| `guideline` | `docs/guidelines/**.md` |
| `context` | `src/agent-src/contexts/**.md` |
| `test` | `tests/**.test.ts` |
| `script` | `src/scripts/**.ts`, not `*.test.ts` |

Stratified: **37 items per label, 333 in all.** The hand is shown the path, the
nine labels with a one-line definition each, and the file's first 15 lines. The
ground truth is the label of the path rule.

### `extract` — one exact frontmatter field

Population: `src/skills/*/SKILL.md` and `src/domains/**/command.md` whose YAML
frontmatter carries a scalar `name:` line. **333 items**, seeded uniform sample.
The hand is shown the frontmatter block and the first 10 body lines, and asked
for the value of `name`. The ground truth is that scalar with one layer of
matching surrounding quotes removed.

## Verifier — `fhs-verify/1`

Deterministic, in `internal/bench/free-hands-shadow/verify.ts`; it costs the
head **zero tokens**, so every row's `verify_tokens` is 0.

- **`classify` pass:** the schema-valid return's `label`, trimmed and
  lower-cased, equals the ground-truth label. `confidence` is not scored.
- **`extract` pass:** the return's `items` has exactly one element, and that
  element, trimmed, equals the ground truth byte for byte. A second item, a
  quoted value or a case change is a fail.
- A return that does not match the kind's schema is a fail (the production
  `shadowAsk` already records it so and never asks the verifier).

**Falsification.** The verifier must reject a planted wrong answer of each kind
before any green reading of it counts
(`tests/scripts/free_hands_shadow_harness.test.ts`, shown red first).

## Calls — the production path, unchanged

Each ask goes through `askHand` → `askOnce` with `kind`, `contentClass:
'public-artifact'`, `stateRoot` = repository root, the flip state **unset** (so
the paid route serves and the free route shadows), and `shadowVerify` = the
verifier above, bound to the item. Rows land in the production shadow ledger
(`agents/runtime/state/free-hand-shadow.jsonl`); the harness's own run ledger
(`agents/runtime/bench/free-hands-shadow/run.jsonl`) holds the item id and both
parsed answers, which the audit needs and the production row deliberately does
not carry.

- **Paid arm: subscription only.** The harness refuses to start unless every
  paid member resolves to a first-party vendor CLI (`transport: cli`,
  `billable: false`) with no API-key or cloud-billing variable for that vendor
  in the environment, and every free member is unpaid. No API-billed call can
  be part of this window.
- **Free arm:** a keyless `base_url` route; its model is the first id of a
  first-party roster discovered at run start (`discoverRouteModels` with the
  route's `first_party_list`).
- **Order and caps:** `classify` first, then `extract`; a kind stops at **333**
  rows, the window at **2,000** (decision A5). Kinds other than these two are
  **unmeasured**: no verifier with genuine ground truth exists for them, and a
  keyword-inclusion check for summaries is rejected (council decision 3).
- **Pacing:** free calls start at least **31 s** apart, across restarts (the
  last ledger row's timestamp counts).
- **Back-off:** a free answer classified `rate_limited` or `quota_exhausted`
  doubles the wait (from 120 s), and four in a row stop the run; a `billing`
  outcome (HTTP 402) stops the run at once, because it contradicts the keyless
  billing proof. Either row stays in the ledger and counts as a free failure,
  exactly as the claim defines it; the report gives its count separately.
- **Resume:** items already in the run ledger are skipped. A production ledger
  whose per-kind row count differs from the run ledger's is a foreign window;
  the harness refuses rather than mixing it.

## Bars — as registered in `docs/CLAIMS.md`, unchanged

Per kind, on this window:

1. **`free-hands-quality-held`** — free escalation-plus-verify-fail rate
   **≤ paid rate + 5 percentage points**, and free rate **< 0.3**. A `skipped`
   verify on a free return counts as an escalation (none is expected here: the
   verifier always rules).
2. **`free-hands-limit-relief`** — per calendar week of the window, paid tokens
   of the calls whose free return passed, **minus** the head's verify tokens,
   **> 0** in every week. The paid arm is subscription-billed, so "paid tokens"
   are limit tokens, not USD; verify tokens are 0 by construction, which the
   report states beside the number.

**Underpowered:** fewer than 333 rows for a kind. Neither a pass nor a null;
backs no flip.

**Null:** a kind with 333 rows missing either half of bar 1, or a week at or
below zero for bar 2. A null is published in the evidence file and the claim
row, and that kind does not flip.

The readiness reading is `kind_flip.flipVerdict` over this ledger, reported as
printed. This harness never flips a kind and never edits `docs/CLAIMS.md`.

## Blind paid-head audit — 10 % per kind

`ceil(0.1 × n)` rows per kind, drawn with seed `20261023`; both answers of each
row are audited as separate questions in shuffled order. The head is
`claude -p --setting-sources project,local` started from an empty temporary
directory, with the vendor API-key variables removed from its environment. It
sees the task input and one answer, never the route, the other answer or the
deterministic verdict, and replies `{"correct": true|false}`.

**Disagreement policy.** The deterministic verdict stays the record; the audit
changes no row and no bar reading. Agreement is reported per kind and per side,
with every disagreeing item listed. Agreement below **0.90** on a kind is
reported as `verifier-suspect` beside that kind's bar reading, which must then
be cited together with it.

## Useful-work byproduct

The report lists every corpus file whose path class and frontmatter disagree:
a skill whose `name` is not its directory name or that lacks `description`; a
rule whose `type` is not `always`, `auto` or `manual`; a command without `name`;
an ADR whose `adr` field is not the number in its filename or that lacks
`status`. Classes without a frontmatter contract are not checked.

## Evidence file

`internal/bench/free-hands-shadow/run.ts report` writes the summary: per kind
the call count, paid and free pass rates, verify-fail and escalation rates, the
rate-limit and billing counts, each bar met / null / underpowered, audit
agreement, spend (USD 0.00 on both arms by construction, tokens reported), the
`kind_flip` readiness reading, and the byproduct list — headed `manufactured`.

## Amendment — 2026-10-23, before any scored call

Committed after an independent review of the harness and before the first shadow call; no
datum existed when it was written. It changes run mechanics only — no corpus, verifier, bar,
audit share or label moves.

1. **Retry instead of skip.** An item counts as done only once a shadow row was ledgered for it;
   an item that produced none (the free route not admissible, the paid arm empty) is retried on
   the next run. The original text skipped every item already in the run ledger, which made a
   kind with exactly 333 items unable to reach 333 after one transient miss.
2. **A failure streak stop.** Ten consecutive free failures of any class end the run
   (`FREE_FAILURE_STREAK_MAX`), so a dead route does not spend a paid call every 31 s. Pacing,
   back-off and streaks are derived from the run ledger, so a restart honours them.
3. **Refuse rather than remove.** Where a paid-billing variable is set, the paid head and the
   audit refuse to start instead of starting with the variable removed — the stricter of the two.
