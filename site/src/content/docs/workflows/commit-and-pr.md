Commit your changes as logical Conventional Commits, then open the pull request:

```text
/commit
/pr:create
```

## What it does

- `/commit` looks at everything uncommitted, groups it into logical commits — one concern each, foundation first — and shows you the split and the messages before it commits.
- `/pr:create` checks the branch for leaked secrets, asks before pushing it and opens a GitHub pull request with a structured description built from the ticket and the changes.
- Neither adds "generated by" footers or decorative emoji to your history.

## When to use it

When the work is done and reviewed. Agent Config never commits, pushes or opens a pull request on its own initiative — these commands are how you ask it to.

## Example

```text
/commit
```

The agent proposes, for example, a `feat(orders): add CSV export` commit with the handler and its test, and a separate `docs: describe the export` commit, then waits for your go-ahead.

## What it needs

- git, and for `/pr:create` the GitHub CLI (`gh`) signed in to your account.
- Your repository's own commit convention, if it has one — the agent follows it instead of Conventional Commits.

## Limits

- `/pr:create` targets GitHub. On GitLab, Bitbucket or another git host, commit with `/commit` and open the merge request yourself.
- It asks before it pushes a branch that is not on GitHub yet.
