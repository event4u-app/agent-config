# Changelog

All notable changes to `event4u/agent-config` are documented here.
Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
versioning policy is documented in [CONTRIBUTING.md](CONTRIBUTING.md#versioning-policy).
Entry-shape contract: [`docs/contracts/CHANGELOG-conventions.md`](docs/contracts/CHANGELOG-conventions.md).

> Entries before 1.3.3 were reconstructed from git history after the fact.
> Early releases did not maintain release notes.
>
> History is split into **eras**. The current era keeps full entries
> inline; prior eras collapse into a single pointer to an archive file
> under [`docs/archive/`](docs/archive/). A drift test
> (`tests/lib/changelog_eras.test.ts`) forces an era split before the
> current era grows past 250 lines.

> **Retro-curation disposition, 2026-09-01** — roadmap
> `road-to-publication-integrity-hard-fail`, blocker `b-retro-curation-scope`,
> option (c). The `### Release highlights` heads of 14.9.0 through 14.13.0 were
> written by the release generator and published without the editorial pass they
> ask for. Two things were repaired: the generator's own authoring instruction,
> which was never release content, is deleted from this file, and the writer no
> longer emits it. The generator-derived head lines below are **preserved as
> published** and deliberately not paraphrased — rewriting a derived claim is
> editorial judgement two prior councils reserved, and a paraphrase of the
> generator's own reason would be truthfully documented uselessness.
> [`docs/archive/`](docs/archive/) is left untouched as historical record. The
> annotated tag messages and the published GitHub Release bodies for 14.9.0
> through 14.13.0 are **immutable** and cannot be repaired at all.

## [18.0.0](https://github.com/event4u-app/agent-config/compare/17.4.0...18.0.0) (2026-10-25)

### Release highlights

- **Behaviour changes:** name 18.0.0 in MIGRATION and BREAKING_CHANGES (d63a430); retire projection.mode — skill scope is decided per host (79cb86c); keep the per-spawn payload at its ratchet (cc68687); agent and bot actions reach the security rules and the threat corpus (fbb677e); an invocation is executed in the order its work needs (dd9dacd); retire projection.rule_packs; the rule pack axis is derived from the active packs (a3d4596).
- **Default changes + migration:** name 18.0.0 in MIGRATION and BREAKING_CHANGES (d63a430); the default-off egress stage reads one block, not the template (71bc1d6); keep the counted phrase in the default-install claim (b3eea0a). Breaking, pending in `BREAKING_CHANGES.md` and shipped by this release: **`projection.mode` is removed, and with it the full-surface guarantee on hosts without a listing lever.** Skill and command scope is decided per host: claude-code and codex receive every artefact and scope by visibility (`skillOverrides`, the codex finder index); every other host receives the active profile's packs plus `runtime.active_packs`, whatever it received before. An upgraded install that had no key, or `legacy-all`, used to get every skill on every host. `agent-config use --profile=legacy-all` is removed (exit 2), and the install-time notice that suggested `projection.mode: scoped` is gone with the key (owner answer 2026-10-24, step 4.7 of `road-to-a-setup-that-decides-itself`). **`projection.rule_packs` is removed; the rule layer's pack axis is derived.** A consumer install now ships a non-kernel rule only when its `packs:` meet the active-pack set — the set the skill and command prune already uses, what `rule_packs: auto` selected. With the default `[]` the axis was off, so a default install stops receiving the eight rules whose packs it does not have: `finance-safety-floor`, `legal-safety-floor`, `strategy-safety-floor`, `image-likeness-and-rights`, `media-governance-routing`, `media-sync-ground-truth`, `provider-lifecycle-discipline`, `spreadsheet-source-quality` (owner directive 2026-10-24, step 4.9 of `road-to-a-setup-that-decides-itself`).
- **Security and correctness:** read a layer the cascade lists twice once, at its last position (66aeb91); detect and resolve the egress mode from one read (1703633); keep the full layer parse, drop only the cascade (b25237c); the egress block reader takes only plain column-0 keys (bc0c066); an indentless sequence under a layer key takes the full egress parse (48ee14d); a removal claim is about the names in its own sentence (9f76f3c); +44 more.
- **Honest nulls:** _none_
- **Known limitations:** the Pending-row parser is its own module (src/scripts/_lib/release_highlights.ts declares a residual) (144e0db); a release head names only the breaks and nulls it carries (src/scripts/_lib/release_highlights.ts declares a residual) (5a52ebf); retire projection.mode — skill scope is decided per host (src/scripts/install.ts declares a residual) (79cb86c); keep install.ts at its line count, pin the manifest proxy count, claim the concern growth (src/scripts/install.ts declares a residual) (445f43e); answer the round-2 ratification findings (tests/install/global_install_hooks_smoke.test.ts declares a residual) (49297e1); gate the StopFailure binding on the oldest host version that accepts it (src/scripts/install.ts declares a residual) (cbc4575); +1 more.

> **Governance mix:** governance-only 129 vs consumer-only 11 (mixed 87, maintenance 17; taxonomy 1.1.0; range 1db5f8f1d69d..4c7ce1ef27f3).

Classed breaking by the AI council, 2026-10-19 (`agents/evidence/council/hook-carrier-release-note-class-20261019.md`). **`uninstall --global --purge` stops being a recursive delete of the host anchor.** Old scope: `fs.rmSync(anchor, { recursive: true })` on whole host configuration roots — `~/.claude/`, `~/.codex/`, `~/.config/zed/` — so everything under them went, whoever wrote it. A second change in the same area: a plain `uninstall --global` now keeps the lockfile while recorded content is still on disk, where it used to delete it.
