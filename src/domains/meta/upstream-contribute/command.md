# /upstream-contribute

This command is a **front on one outward step**, not a second way out. It
decides *what* is worth contributing and hands the finding to
`self-repair:release`, which owns the branch, the commit identity, the privacy
floor over every byte that leaves, and the pull-request or issue route.

```
ONE WAY OUT. THIS COMMAND NEVER PUSHES, NEVER OPENS A PULL REQUEST,
AND NEVER WRITES A SECOND COPY OF AN ARTIFACT.
WHAT LEAVES THE MACHINE LEAVES THROUGH `self-repair:release`.
```

## Input

The user may provide:

- A file path to a new or improved skill/rule/command
- A description of what should be contributed
- Nothing (auto-detect from recent work)

## Steps

### 1. Identify what to contribute

If the user provided a file path, read it. If not, look for recent overrides
or new project-local artifacts:

```bash
ls agents/overrides/
```

```bash
git diff --name-only HEAD~5 -- agents/overrides/
```

Ask the user to confirm what should be contributed:

```
> Found these candidates for upstream contribution:
>
> 1. {file1} — {brief description}
> 2. {file2} — {brief description}
> 3. Something else — I'll describe it
>
> Which one?
```

### 2. Check universality

This is a **worth-contributing** judgement, not a privacy check — the privacy
floor over the bytes runs in step 4 and cannot be satisfied by a checkbox here.

- [ ] Benefits every consumer, not only this project
- [ ] The learning occurred twice or more, or is clearly generalizable
- [ ] A named mechanism explains why the shipped default is wrong

Below that bar, record the signal and leave the shipped default alone.

### 3. Determine contribution type and source path

`src/` is the only place an artifact is authored. The projections under
`dist/agent-src/` are regenerated by `task sync`; a contribution never writes
a second, hand-condensed copy (ADR-201 copies `.md` verbatim).

| Type | Source path |
|---|---|
| **Skill** | `src/skills/{name}/SKILL.md` |
| **Rule** | `src/rules/{name}.md` |
| **Command** | `src/domains/{domain}/{name}/command.md` |
| **Guideline** | `docs/guidelines/{category}/{name}.md` |

### 4. Hand the finding to the ladder

Show the user what would leave the machine, before anything leaves it:

```bash
./agent-config self-repair:release <fingerprint> --dry-run
```

The dry run prints the resolved route, the account that will appear on the
pull request, and every byte of the title, body, branch name and diff. It
touches no network. Read it with the user; a refusal from the privacy floor
is final and the finding stays local.

No record yet? Record the finding first, then release it:

```bash
./agent-config self-repair:status
```

### 5. Send, once, with the user's word in that turn

```bash
./agent-config self-repair:release <fingerprint>
```

Running that command IS the user's word. It is a Hard-Floor action under
`non-destructive-by-default`, so no standing instruction, autonomy setting or
earlier approval substitutes for it.

The ladder chooses the vehicle: a pull request from a checkout of this
package, an issue otherwise, and a local record when nothing may leave.
Degrading never widens what leaves the machine, only the vehicle.

### 6. Quality gates (only in a checkout of this package)

```bash
task ci
```

Outside such a checkout the package CI runs these after the issue or pull
request exists.

### 7. Remind about local override cleanup

```
> After the contribution is merged and you update the package here:
>
> 1. rm agents/overrides/{type}/{name}.md
> 2. npm update @event4u/agent-config
>
> The shared version then replaces your local override.
```

## Do NOT

- Do NOT push, open a pull request, or open an issue by hand — that is the
  ladder's job and the floor over the bytes runs there.
- Do NOT write a hand-condensed second copy of an artifact.
- Do NOT edit any generated projection; `src/` is the source of truth.
- Do NOT stage with a bare `git add .` — name the paths.
- Do NOT assume consent from an earlier contribution; the word is per turn.
